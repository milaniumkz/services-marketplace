# Модуль JOBA: автоматическая съёмка и сравнение лица

Это отдельная вырезка исходников, а не готовая CRM и не независимое приложение «запустить одной кнопкой». Снимок исходного кода: 022dd87bc0fdd7a16db7ca0a10c572e94017e8d8.

## Что внутри
- `apps/mobile/lib/core/web_selfie_camera.dart`: фронтальная камера, овальная рамка, автосъёмка, закрытие и результат.
- `face_motion.dart`, `face_sequence.dart`: пять шагов — прямо, немного налево, направо, моргнуть, улыбнуться.
- `web_face_voice.dart`: русские голосовые подсказки, предпочтение женского голоса при наличии на устройстве.
- `apps/mobile/web/joba-face-tracker.js`: MediaPipe, точки лица и мимика. Этот JS можно использовать и без Flutter, но интерфейс камеры и последовательность тогда надо перенести отдельно.
- `screens/face_access.dart`: сохранение шаблона и восстановление пароля.
- `services/face`: самостоятельный Python HTTP-сервис получения 128-мерного дескриптора, Dockerfile, тесты, закреплённые модели/лицензии.
- `services/api/src/face-recovery.ts`: регистрация шаблона, две ошибки пароля, challenge, сравнение, одноразовый сброс пароля. Store и PrivateFiles приложены как справочные зависимости существующего API JOBA; для другого проекта нужны адаптеры.

## Как перенести
1. Скопировать нужные Flutter-файлы с сохранением путей. Подключить зависимости из приложенного pubspec. JobaApi, работу с аккаунтом и маршруты адаптировать к своему API. Автоматические движения и озвучка в этой реализации относятся к БРАУЗЕРУ; нативный `face_camera_native.dart` снимает пять кадров вручную через системную камеру.
2. Выполнить из корня вырезки `python3 scripts/prepare-face-browser-assets.py`. Скрипт загрузит закреплённые MediaPipe/WASM-модели с проверкой хешей. Раздавать каталог `apps/mobile/web/face-models` по `/face-models/`, JS — рядом с веб-приложением. Перед запуском приложения подключить `<script src="/joba-face-tracker.js" defer></script>`. Для камеры нужен HTTPS или localhost. Не помещать страницу в iframe без разрешения camera.
3. Python-сервис: из корня `docker build -f services/face/Dockerfile -t face-engine .`. Запускать во внутренней сети API на порту 8080. `/health` — готовность, `POST /embedding` — тело JPEG/PNG, `Content-Type: application/octet-stream`. Не открывать этот сервис напрямую пользователям.
4. В API подключить FaceRecovery либо перенести его логику. `JOBA_FACE_SERVICE_URL` — внутренний адрес Python-сервиса. Создать СВОЙ ключ шифрования и хранилище; секреты, аккаунты, фото и биометрические шаблоны JOBA в архив НЕ включены. В Store нужны записи шаблонов/challenge/счётчиков/согласий и транзакции PostgreSQL; PrivateFiles показывает AES-GCM и привязку шифрования к аккаунту. Это зависимости, которые надо адаптировать, а не вставлять без изменений в любую БД.
5. Подключить маршруты (ниже) к авторизации проекта. После двух неверных паролей вызывать `failedLogin`, отдавать challenge в ответе входа. После обычного входа вызывать `clearLogin`. При смене пароля, блокировке и удалении аккаунта инвалидировать доказательства и шаблоны по правилам проекта.
6. Проверить пять шагов, отказ камеры, отмену, другое лицо, истечение challenge, повторное использование reset_token, удаление шаблона и отзыв сессий. Приложенные тесты Flutter/API запускаются в контексте исходного проекта; Python-тесты самостоятельные: установить requirements, выполнить `download_models.py`, затем `python -m unittest test_engine` из services/face.

## HTTP-контракт (в JOBA префикс /api/v1)
- `GET /me/face-recovery`: состояние и необходимость первого сохранения.
- `POST /me/face-recovery`: `{consent:true,current_password,photos:[{step:"front",photo:"BASE64"},...]}`. Шаги строго front,left,right,blink,smile. У новых аккаунтов текущий пароль может не требоваться по политике сервера.
- `PATCH /me/face-recovery`: отметить отказ от предложения настройки.
- `DELETE /me/face-recovery`: `{current_password}`.
- `POST /auth/face-recovery/verify`: `{id,nonce,photos:[...]}` -> `{verified,reset_token}` при совпадении.
- `POST /auth/face-recovery/reset`: `{id,reset_token,new_password}` -> смена пароля и отзыв сессий.
Сохранение/проверку/сброс вызывать в транзакциях как в исходном API. Сохранять rate limit, сроки действия и одноразовость токенов.

## Границы реализации
Это сравнение лица с автоматическими подсказками, не проверка документов и не защита от фотографии/видеозаписи/дипфейка. Сервер сравнивает пять выбранных кадров, не проверяет подлинность видеопотока. Порог 0.45 взят из текущей реализации и не является измеренной гарантией точности. Исходные кадры не сохраняются сервером шаблонов, сохраняются зашифрованные дескрипторы. Не выдавать модуль за OS Face ID.
