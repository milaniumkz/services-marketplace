# Services marketplace

Техническая основа отдельной биржи услуг. Бренд ещё выбирается. Заказчики ищут исполнителей, исполнители ищут заказы по своим услугам; постоянные вакансии не входят в продукт.

Это initial scaffold, не готовый backend или опубликованный сервис. Полное ТЗ готовит отдельный автор: [статус](docs/specification-status.md).

| Страна | Код | Языки | Валюта |
|---|---|---|---|
| Сербия | RS | sr | RSD |
| Казахстан | KZ | ru, kk | KZT |
| Россия | RU | ru | RUB |
| Беларусь | BY | ru, be | BYN |

Планируемый объём: услуги, заказы и отклики, чат, профили/аватары, репутация заказчика и исполнителя, жалобы, блокировка и апелляции. Эти функции пока не реализованы.

Google OIDC идентифицирует аккаунт по `issuer + sub`; email — атрибут. Для iOS предусмотрен дополнительный Apple login по правилам магазина. FaceID — локальная повторная аутентификация; проверка личности — отдельный процесс. GPS используется только с согласием, с точностью и временем измерения; IP не определяет точное место.

Подписки и рекламный доступ конфигурируются админом. Реальная монетизация требует проверки провайдеров по каждой стране; для России учитываются ограничения Play Billing, AdMob и Apple. Доступ к удалению аккаунта, приватности, поддержке и восстановлению оплаты нельзя закрывать оплатой. Документы личности не хранятся бессрочно.

## Состав

- `services/api` — NestJS/TypeScript, только `GET /health`, без БД и бизнес-API.
- `apps/admin` — TypeScript/Vite, статичная демо-страница без пользовательских данных.
- `apps/mobile` — Flutter demo sources для iOS/Android; нативные runners требуют генерации установленным Flutter SDK.
- `packages/contracts` — минимальные типы health и кодов стран.
- `infra` — не запущенный шаблон PostgreSQL/PostGIS.
- `docs` — инструкции и границы реализации.

[Запуск и проверки](docs/local-development.md) · [Безопасность](docs/security.md).

Секреты и персональные данные не добавлять. `.env.example` содержит только placeholders. Платные Actions, self-hosted runners, production deployment, реальные платежи, реклама и сбор персональных данных не настроены. После утверждения ТЗ разработка идёт в отдельной feature branch через draft PR.
