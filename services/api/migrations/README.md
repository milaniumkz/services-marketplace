# Миграции JOBA

`Store.initialize()` применяет идемпотентные runtime-миграции к выделенной базе приложения: `0002_runtime.up.sql`, `0003_rate_limits.up.sql`, `0004_account_views.up.sql`, `0005_invite_queries.up.sql`, `0006_ranking_votes.up.sql`, `0007_product_queries.up.sql`, `0008_push_campaigns.up.sql`. В локальных тестах используется PGlite; для production обязателен отдельный региональный PostgreSQL с `DATABASE_URL` и `JOBA_REGION`.

`0004` добавляет индексы участников заказов, получателей приглашений и адресатов отзывов для сводок и пагинации. `0005` добавляет индексы активных пар приглашений и суточного лимита автора. `0001_extensions.up.sql` — отдельная подготовка PostGIS из первоначального scaffold; текущая runtime-инициализация её не запускает.

Перед подключением production-базы нужно разделить migration/runtime роли и проверить восстановление резервной копии. Текущая автоматическая инициализация требует DDL-прав; отделение production migration runner остаётся открытой серверной работой. Не применять файлы к посторонним базам. Автоматический rollback не предусмотрен.

`0008` индексирует аудиторию и очередь кампаний; уникальный региональный индекс campaign/recipient предотвращает повторную постановку одному получателю. Записи без campaign_id под ограничение не попадают.
