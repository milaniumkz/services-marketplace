# Резервирование реферальных наград

Реализован отдельный блок серверной механики, 16.10.2026.

Перед принятием первого приглашения в группе резервируется одна единица бюджета награды. Следующие приглашения того же пригласившего заполняют эту группу до порога из зафиксированной политики. Новая группа требует отдельного резерва; при исчерпании бюджета API возвращает `REFERRAL_BUDGET_EXHAUSTED` без создания атрибуции.

Квалификация использует снимок принятого обещания. Остановка кампании запрещает новые атрибуции, но не блокирует достижение порога уже принятой группы и выдачу награды. Награда содержит только атрибуции своей группы. Выданные и зарезервированные единицы продолжают учитываться в бюджете; автоматического освобождения незавершённых групп нет.

Операции принятия, квалификации и погашения используют общий региональный advisory lock в транзакции API. Повторная квалификация и погашение не создают повторных привилегий.

Для исторических атрибуций без `reservation_id` сохранена прежняя ветка квалификации; миграция уже принятых исторических обязательств этим изменением не выполняется. Исторические награды без резерва учитываются при проверке доступного бюджета новых групп.

Проверки: сборка API, целевой тест резервирования и существующие бизнес-сценарии (8 успешно). Полный набор API: 90 успешно, 0 ошибок, 0 пропусков. Новый тест проверяет конкуренцию пригласивших за последний бюджет, заполнение группы, запрет лишних приглашений, остановку кампании, неподходящее событие, точный порог, состав награды и повторное погашение.

Открыты: структурированная форма A20 и её визуальная приёмка, окно атрибуции и политика освобождения резерва, проверка исторических данных. Это изменение не подключает платёжного провайдера, не вводит подписку заказчику и не означает завершение всего реферального блока. На рабочий сервер не развёрнуто.
