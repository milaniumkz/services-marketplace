# ВТБ Казахстан: подписки и продвижение JOBA

Актуальная тестовая версия: [APK JOBA 1.0.5 (7), оплата внутри приложения](https://raw.githubusercontent.com/milaniumkz/services-marketplace/a514e72151d78bf8253c39425968cd2467011054/JOBA-1.0.5-7-test.apk).

Подключение использует страницу банка, а не сбор карточных данных в JOBA. Сервер хранит заказ до обращения в банк и проверяет `getOrderStatusExtended.do`: номер заказа, сумму в тиынах, валюту 398, завершённое списание (`orderStatus=2`, `actionCode=0`, `depositedAmount`). Возврат пользователя из банка сам по себе доступ не выдаёт.

## Что доступно

- Заказчик: подписка на 30 дней.
- Исполнитель: Стандарт, Премиум, отдельный Топ-100.
- Продление, немедленное повышение с пропорциональной доплатой, немедленное понижение с переносом оплаченного остатка в дни Стандарта.
- Реферальные персональные скидки, включая 100% без обращения к банку при нулевой итоговой цене.
- Разовое продвижение по опубликованной цене и резерву места.
- Восстановление незавершённого платежа, отмена неоплаченного банковского заказа, фоновая сверка раз в минуту.
- Возвраты через существующие заявки и административное согласование; повторный `externalRefundId` не создаёт второй возврат.

Подключённая валюта — KZT. Настройки других стран и подписки за рекламу сохраняются. Автоматических списаний и хранения карт нет: продление запускает пользователь.

## Цены и проверка в приложении

1. Админка → «Подписка и реклама» → цены подписок: задайте цены заказчика, Стандарта, Премиума и отдельного Топ-100. Банковские SKU для этих тарифов создавать не нужно.
2. Для продвижения используется опубликованная версия цены с провайдером `vtb`, типом `boost`, валютой `KZT` и настроенным размещением.
3. Пользователь → «Мой доступ» → выбрать тариф → подтвердить условия → «Продолжить оплату».
4. Ввести **только тестовую карту** на форме ВТБ в тестовом режиме. Вернуться в JOBA; статус проверится автоматически. В Android начиная с версии 1.0.5 форма банка открывается внутри JOBA; при возврате банка окно закрывается автоматически. Закрытие окна вручную сохраняет незавершённый платёж.
5. Если связь пропала, «Мой доступ» показывает незавершённую оплату. Не создавайте повторную оплату: откройте сохранённую.
6. Платежи/возвраты → выбрать подтверждённый платёж → запросить возврат. В админке согласовать, отправить и сверить результат.

Сумма замораживается при начале оплаты. Изменение цены администратором уже созданный заказ банка не переоценивает. При несовместимом изменении аккаунта после оплаты фиксируется оплаченная операция для восстановления услуги или возврата; повторного списания нет.

## Закрытая конфигурация

На сервере `/etc/joba/payments/vtb.json`, владелец UID/GID 1000, права 0600; каталог 0750. Compose монтирует каталог только для чтения в API. Пароли не входят в Git, APK или веб-сборку.

Поля: `environment`, `user_name`, `password`, `public_origin`, `payment_form_path`. Тестовый канал GitHub Actions `deploy.yml` → `vtb_setup` принимает только sandbox, через одноразовый RSA-OAEP/AES-GCM конверт, привязанный к заданию/коммиту/nonce. В Git передаётся исключительно шифротекст.

Безопасный статус настройки: `GET /api/v1/admin/vtb-status` с правом billing; возвращает режим и валюту, без секретов.

## Перед включением настоящих оплат

1. Сообщить банку, что интеграция тестового контура готова, и запросить **боевые** API-реквизиты и подтверждение одностадийной оплаты в KZT. Нельзя использовать тестовый пароль в боевом контуре.
2. Подтвердить в анкете мерчанта настоящий домен **https://joba.com.kz** (в переписке встречается другое написание).
3. Согласовать URL возврата `https://joba.com.kz/api/v1/public/billing/vtb/return` и callback `https://joba.com.kz/api/v1/public/billing/vtb/callback`. Параметры `payment_id` и HMAC-токен формируются сервером для каждой операции.
4. После подтверждения банка установить приватную production-конфигурацию на сервер. Боевой адрес адаптера: `https://payment.vtb.kz/payment/rest/`; при изменении адресов банк должен подтвердить их до изменения кода.
5. Перезапустить API, проверить режим в админке. Провести небольшую настоящую оплату и возврат с владельцем карты, сверить их в кабинете ВТБ. Только после этого объявлять рабочую оплату.
6. Обновить Android прежним ключом подписи магазина. Тестовый APK не заменяет публикацию обновления.

Настройка sandbox не считается разрешением на боевые списания. Письма банку автоматически не отправляются.

## Оплата внутри приложения (1.0.5)

Банковская форма и HTTPS-переходы 3-D Secure открываются во встроенном WebView. JOBA не передаёт в него свои токены и не читает реквизиты карты. Возврат банка закрывает окно; доступ по-прежнему выдаётся только после серверной сверки. Ошибка сети или ручное закрытие не считаются подтверждением либо отменой платежа. Для тестового контура в заголовке окна доступна подсказка «Тестовая карта» с копированием номера.

Сообщение при вводе настоящей Visa в sandbox не означает отказ Visa в боевом контуре. В sandbox используйте указанную выше тестовую карту. Возможность настоящих оплат Visa должна быть подтверждена банком для боевого мерчанта; текущая интеграция остаётся тестовой.
