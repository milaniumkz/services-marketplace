# Переписка и тексты протоколов дел — блок 10

Добавлен отдельный повторяемый этап case_text, до 50 записей за проход, по опубликованному audit_days. Применяется к завершённым делам no_violation/overturned после срока от решения и последней переписки. Апелляционные решения content_removed/sanction_upheld, открытые связанные дела, удержания/ограничения, недавняя переписка и неизвестная дата закрытия сохраняют материалы.

Собственный текст удалённого участника может минимизироваться независимо от другого участника: сообщение становится tombstone, удаляются текст и живые ссылки вложений, технический след файлов сохраняется. Текст другого действующего участника не изменяется.

Служебные основания решений, внутренние заметки корня дела и однозначно определённые служебные сообщения минимизируются лишь после подтверждённого удаления обеих сторон дела. Неизвестный субъект старого дела не считается удалённым: основания такого решения сохраняются для проверки. Сохраняются идентификаторы, автор решения, дата, код решения, версия материала и статус протокола. Неизменяемый audit не переписывается. Старые сообщения без достоверной классификации служебного автора автоматически не угадываются и остаются на проверку. Новые сообщения получают author_type на сервере по маршруту, а не из запроса клиента.

Вложения очищенной переписки используют audit_days и существующую физическую очередь, с проверкой остальных ссылок и удержаний. В админке вместо пустого текста показывается сообщение об удалении по сроку хранения; служебный автор определяется также по серверной отметке. Прогресс case_text хранит обработанное/оставшееся количество и основание политики. Повтор не учитывает запись дважды.

Открыто: классификация старой служебной переписки и иных исторических данных, следы модерации, согласия/неизменяемый аудит, история документов, финансовые метаданные и служебные кэши. Общий support остаётся частичным этапом, fully_erased=false. Многопроцессный PostgreSQL, нагрузка больших очередей, визуальная приёмка и развёртывание на сервер в этом изменении не проверялись.

Проверки: сборка всех workspace и 123 API-теста прошли без ошибок/пропусков. Браузерный сценарий подтвердил отображение очищенного сообщения и завершился с 72 исходными кадрами. После дополнительной защиты дел с неизвестным субъектом повторены сборка API и 23 связанных теста — все успешны. Тесты включают чужого участника, обе удалённые стороны, неизменяемый аудит, неопределённого старого автора, апелляции, удержания, недавнее решение, порцию 50 записей, повтор и физическую очистку вложения. Визуальное совпадение всех экранов этим не подтверждено. Сервер не обновлялся.
