# Реестр завершения: блок 1

`python3 scripts/build-completion-registry.py` собирает `design/review/completion-registry.json` из исходного ТЗ и реестров макетов. Повторная генерация сохраняет ручные результаты проверки при неизменном тексте требования/контрола. Контрол определяется ID кадра и порядковым номером; при изменении описания его проверка сбрасывается в pending.

Учтены 46 FR (включая FR-015A), 12 NFR, 33 сценария T01–T33, все 187 исходных кадров и 2897 исходных контролов (прежний реестр учитывал 2449 и пропускал 448 элементов, нарисованных как div/span). Дополнительно зарегистрированы W06–W09: оплата, возврат, оферта и контакты. Для них нет исходных PNG; список HTML-контролов извлечён отдельно и ожидает функциональной проверки. Всего в расширенном реестре 191 состояние. Дополнительные служебные снимки редакторов не автоматически считаются отдельными эталонными кадрами.

Для каждого требования указаны строка и текст источника, связанные рабочие блоки и существующие кандидаты тестов. У каждого контрола есть поля для проверенных API и свидетельств. OpenAPI подключён как каталог, но это не подтверждённая связь операции с требованием. Кандидаты тестов выбраны для навигации по именам файлов и не означают покрытие. Все неподтверждённые связи и результаты явно pending.

Отдельно записаны изменения владельца: бесплатность заказчика, подписка только исполнителю, KG вместо RS, включённые страны, разрешённые исходные параметры, отложенные провайдеры и заполнение реквизитов позже. Они применяются вместе с исходным ТЗ; старые формулировки не скрываются.

Блок 1 остаётся открытым: по мере прохождения рабочих блоков необходимо вручную заполнить точные связи requirement → control → API → evidence, проверить контроли новых страниц и зарегистрировать конкретные дефекты. Само наличие реестра не означает завершения функций или визуальной приёмки. Сборка реестра проверяет полноту извлечённых ID; повторяемость проверена двумя генерациями с одинаковым SHA-256.

Парсер теперь учитывает render-button, render-input, render-select, render-checkbox и соответствующие ARIA roles. Регрессия `python3 scripts/test-audit-design.py` проверяет вложенный текст, SVG, data-action и отсутствие обычного текста среди контролов.

После добавления новых страниц извлечены также 92 их HTML-контрола. Они ожидают проверки; суммарно отслеживаются 2989 контролов. Реестр и исходный аудит не назначают успешный статус автоматически.
