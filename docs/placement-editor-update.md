# Места и ёмкость продвижения

Форма `#placements` использует отдельные поля названия, места и одновременной ёмкости (целое 1–100) вместо JSON. Доступны пять мест, поддерживаемых выдачей. Страна берётся из сессии сотрудника; изменения черновика требуют причины и ожидаемой версии. Редактировать можно только собственный черновик. Публикация требует другого сотрудника с правами продвижения и MFA.

GET/PATCH `/admin/placement-policies/{id}` добавлены в OpenAPI. Предпросмотр возвращает пиковое число пересекающихся обязательств, действующие резервы и активные/запланированные размещения из базы. Несохранённые изменения блокируют команды версии. Ошибки сохраняют введённые поля.

Публикация и остановка используют ту же транзакционную блокировку ёмкости, что и резервирование продвижения. Снижение ниже пика запрещено; остановка опубликованной политики с обязательствами запрещена. Истёкшие резервы и завершённые интервалы не занимают ёмкость. Соседние интервалы без пересечения не складываются. Это проверка политик; внешняя оплата не имитируется.

Проверки: сценарий API охватывает ограничения полей, владельца, версии, независимую публикацию, соседние интервалы, действующий/истёкший резерв, запрет остановки и фактический вызов резервирования через Growth. Браузерный сценарий проверяет создание, редактирование, блокировку несохранённой версии, предпросмотр и запрет самостоятельной публикации.

Дополнительный снимок: `design/review/admin/placement-editor.png`. Визуальная приёмка A22.placements остаётся открытой; наличие снимка не подтверждает 1:1. Изменения этой ветки ещё не развёрнуты на рабочем сервере.

Итог прогона: сборки всех рабочих пространств успешны; 96 тестов API прошли, ошибок нет; браузерный прогон завершён успешно (72 кадра, без ошибок маршрутов). Проверки выполнялись на изолированной базе, а не на рабочем сервере.
