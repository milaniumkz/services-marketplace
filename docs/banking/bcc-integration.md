# БЦК: подключение JOBA и оставшиеся действия банка

## Что реализовано

- Подписки заказчика, Стандарт, Премиум, продление, смена тарифа с пересчётом и отдельный Топ-100 используют общий серверный расчёт стоимости.
- Для новых клиентов Казахстана подключается БЦК. Для Кыргызстана предусмотрен БЦК, для России и Беларуси — ВТБ; предложение появляется только для страны и валюты, разрешённых конфигурацией банковского терминала.
- Старые установленные клиенты сохраняют совместимый путь ВТБ. Новые версии сообщают серверу поддержку БЦК заголовком `X-Joba-Payments: bcc-v1`.
- В установленном приложении платёжная форма открывается во встроенном WebView; в браузере — в защищённом встроенном окне без замены страницы JOBA. Реквизиты карты вводятся на стороне банка. Секретный MAC-ключ остаётся на сервере.
- Возврат с банковской страницы не выдаёт подписку. Сервер отдельно запрашивает статус у банка и проверяет операцию, терминал, сумму, валюту и подтверждение покупки. Повторная проверка не выдаёт услугу повторно.
- Возвраты БЦК используют TRTYPE=14. Запись о попытке сохраняется отдельно от SQL-транзакции до отправки команды. При неоднозначном тайм-ауте команда автоматически не повторяется: сотрудник сверяет операцию в кабинете банка. Неподтверждённый возврат остаётся ожидающим, а не объявляется зачисленным.

## Текущее ограничение банковских параметров

Предоставленная документация БЦК содержит общий тестовый терминал для KZT. 11 ноября 2026 года проверены загрузка банковской формы внутри окна JOBA, тестовая оплата 1 KZT и возврат без смены основной страницы и без новых вкладок. Банк подтвердил операцию по серверному запросу статуса: ACTION=0, RC=00, сумма, валюта, заказ, терминал и тип покупки совпали. В этой проверке банк использовал сценарий без запроса одноразового кода. Это тестовый контур, а не проверка боевого списания. Ранее, 9 ноября, те же опубликованные карты возвращали RC=51; при повторении отказа нужно обращаться в банк.

Для Кыргызстана банк должен подтвердить приём KGS (417) на терминале либо отдельно согласовать расчёт в KZT и порядок конвертации. JOBA не подменяет сомы тенге по соотношению 1:1 и не придумывает обменный курс.

Существующие параметры ВТБ относятся к казахстанскому терминалу KZT. Для рублей и белорусских рублей требуются одобренные банком параметры стран и валют RUB (643), BYN (933). Наличие кода адаптера не заменяет согласования терминала.

## Что запросить у БЦК

Обратиться в существующую переписку с банком или на **support-ecom@bcc.kz**:

> JOBA: тестовая форма открывается внутри приложения, тестовая покупка 1 KZT подтверждена серверным запросом статуса (ACTION=0, RC=00). Просим подтвердить сценарий проверки возврата, валюту и условия приёма платежей пользователей Кыргызстана. После завершения тестов потребуются промышленный TID, MERCHANT ID и компоненты MAC-ключа.

При необходимости приложить безопасный идентификатор тестовой операции из отчёта. Не отправлять в переписку настоящие номера карт, CVV или банковские коды пользователя.

## Включение после получения параметров

Банковские параметры устанавливаются серверным администратором в закрытый `/etc/joba/payments/bcc.json` (в контейнере `/run/joba-payments/bcc.json`), права файла 0600, владелец контейнера. Поля: `environment`, `terminal`, `merchant`, `mac_key`, `public_origin`, `countries`, `currencies`. Домен возврата: `https://joba.com.kz`. Ключ собирается из компонентов локально, без передачи сторонним онлайн-калькуляторам.

Тестовый адрес: `https://test3ds.bcc.kz:5445/cgi-bin/cgi_link`. Промышленный: `https://3dsecure.bcc.kz/webview`. Код выбирает адрес по среде, произвольный внешний URL в конфигурации не допускается.

После установки параметров проверить в админке **Каталог цен → Банковская оплата**: банк, среду, страну, валюту и доступность. Затем провести согласованную с банком проверку успешной оплаты и возврата; проверить выдачу услуги и финансовый журнал. Только подтверждённые банком страны/валюты добавлять в `countries` и `currencies`.

Анкеты, договоры и заявления банка этим изменением не редактируются и не отправляются.
