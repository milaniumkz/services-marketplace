# Доставка push-уведомлений

Диагностика production показала активный Web-токен и принятые FCM сообщения. Старый service worker регистрировал обработчик push после асинхронного fetch: при холодном запуске входящий push мог прийти раньше слушателя. Теперь публичная конфигурация импортируется синхронно, Firebase подключает слушатель при каждом запуске worker. Новая версия активируется без ожидания закрытия старых вкладок.

Открытая вкладка также показывает системное уведомление через service worker. Тег события предотвращает размножение одного уведомления несколькими вкладками. Нажатие открывает защищённый раздел событий. Содержимое переписки, документы и адреса в push не включаются.

Изменения заказа, приглашений, отзывов, услуг, портфолио, подписок, возвратов, продвижения и бонусов создают уведомление, событие потока и outbox в той же транзакции. Откат не оставляет уведомление об отменённом изменении. Повтор одной версии не дублирует события. Запечатанные отзывы не уведомляют получателя до разрешённой публикации. Уведомления получают участники текущей страны; глобальная рассылка всех заказов всем пользователям не добавлялась.

В настройках есть «Отправить проверочное уведомление». Это явный тест только на устройства своего аккаунта; он обходит часы тишины для этой проверки и не меняет пользовательские предпочтения. Обычные события по-прежнему учитывают категории и часы тишины. При отсутствии действующего устройства очередь честно ждёт токен.

Подготовлена реальная FCM-проверка в одноразовом Chrome: регистрация отдельного тестового токена, остановка worker, отправка только этому браузеру и проверка системного уведомления. Её результат фиксируется отдельно от validate-only. APK по указанию владельца не собирается: ранее установленный APK без Firebase SDK требует будущего обновления.
