# Доставка push-уведомлений

Диагностика production показала активный Web-токен и принятые FCM сообщения. Старый service worker регистрировал обработчик push после асинхронного fetch: при холодном запуске входящий push мог прийти раньше слушателя. Теперь публичная конфигурация импортируется синхронно, Firebase подключает слушатель при каждом запуске worker. Новая версия активируется без ожидания закрытия старых вкладок.

Открытая вкладка также показывает системное уведомление через service worker. Тег события предотвращает размножение одного уведомления несколькими вкладками. Нажатие открывает защищённый раздел событий. Содержимое переписки, документы и адреса в push не включаются.

Изменения заказа, приглашений, отзывов, услуг, портфолио, подписок, возвратов, продвижения и бонусов создают уведомление, событие потока и outbox в той же транзакции. Откат не оставляет уведомление об отменённом изменении. Повтор одной версии не дублирует события. Запечатанные отзывы не уведомляют получателя до разрешённой публикации. Уведомления получают участники текущей страны; глобальная рассылка всех заказов всем пользователям не добавлялась.

В настройках есть «Отправить проверочное уведомление». Это явный тест только на устройства своего аккаунта; он обходит часы тишины для этой проверки и не меняет пользовательские предпочтения. Обычные события по-прежнему учитывают категории и часы тишины. При отсутствии действующего устройства очередь честно ждёт токен.

Выполнена реальная FCM-проверка в одноразовом Chrome: регистрация отдельного тестового токена, остановка worker, отправка только этому браузеру и проверка системного уведомления. Её результат фиксируется отдельно от validate-only. APK по указанию владельца не собирается: ранее установленный APK без Firebase SDK требует будущего обновления.

## Подтверждение на опубликованном сайте

- Основное исправление: `dd6b5b1`, [успешный деплой](https://github.com/milaniumkz/services-marketplace/actions/runs/40670737892).
- Полная версия со сроками и восстановлением доступа: `782cbd6`, [успешный деплой](https://github.com/milaniumkz/services-marketplace/actions/runs/40672490544).
- [До исправления](https://github.com/milaniumkz/services-marketplace/actions/runs/40670874328/attempts/1): FCM принял сообщение, но остановленный worker не показал уведомление в тестовом Chrome.
- [После исправления, тот же сценарий](https://github.com/milaniumkz/services-marketplace/actions/runs/40670874328/attempts/2): настоящий FCM push получен, системное уведомление найдено через браузерный API.
- [Финальная проверка после последнего деплоя](https://github.com/milaniumkz/services-marketplace/actions/runs/40673738244): реальная доставка подтверждена повторно, одноразовая тестовая подписка браузера удалена. Клиентские учётные записи в проверку не включались.
- Проверки: 172 API-теста, 255 Flutter (2 пропущены), 13 Chrome, 60 сочетаний страниц/ширины админки. Отдельно 2 проверки холодного запуска/нажатия service worker и проверки транзакционных изменений и сроков.

После обновления страницы пользователь может открыть настройки уведомлений и нажать «Отправить проверочное уведомление». Оно адресуется только собственным зарегистрированным устройствам. Для новых сообщений, откликов и приглашений необходимо, чтобы соответствующий получатель вошёл и разрешил уведомления в своём браузере. Старый APK без Firebase SDK не получит мобильные push до отдельной сборки и установки; APK сейчас не собирался.
