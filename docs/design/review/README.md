# Промежуточная сверка native экранов

Снимки Flutter получены widget-прогоном на viewport 390×844, pixel ratio экспорта 2. Шрифты и SVG взяты из исходного макета. Изолированные данные проверяют компоновку и действия; рабочие экраны получают данные из API. Native SafeArea оставляет место для настоящей системной строки и панели жестов.

| S20 — приглашения | Данные заказа/заказчика, срок, принятие → форма обычного отклика, отказ | [S20](mobile/S20-invitations.png) |

Оригиналы: `mobile/screens/S19-invite.png`, `S20-invitations.png`, `S29-report.png`, `S30-cases.png` внутри [исходного прототипа](../packages/JOBA_Mobile_Prototype.zip).

Воспроизведение из корня репозитория:

```bash
JOBA_SCREENSHOT_DIR=/tmp/joba-native-design-review bash scripts/flutter-mobile.sh test test/design_flow_test.dart --reporter expanded
```

Эти снимки фиксируют текущую реализацию, а не завершённую визуальную приёмку. Реестр [screen-audit.json](../screen-audit.json) сохраняет все 187 экранов/состояний и 2449 контролов. Поэкранное сравнение, остальные состояния и общая функциональная приёмка ещё не завершены. Значения pending нельзя менять на passed по одному наличию route или успешной сборке.

A19 — [текущий экран брендинга](admin/A19-branding.png): Chromium, viewport 1440×1000, полный кадр. Изолированный PNG загружен через API; проверены автоматическая обрезка, настоящие платформенные previews, запрет подтверждения автором, независимый approval, генерация и скачивание ZIP. Расположение блока проверок исправлено по исходному макету. Этот кадр не закрывает визуальную приёмку остальных состояний A19 или всего приложения.

Проверен переход к правилам; реальная атрибуция и redeem проверяются backend-тестом. Эти снимки не закрывают приёмку всех состояний S37 или физическую проверку системного share.

## Полный реестр снимков — 2026-10-14

Опциональный `visual_inventory_test.dart` снимает 42 основных мобильных экрана и 18 дополнительных состояний. Он использует изолированные API-сценарии, загружает Noto/MaterialIcons и дожидается декодирования фотографий. Рабочий клиент получает данные и фотографии из API. Браузерный прогон снимает 67 кадров админки и 5 публичных страниц через изолированный HTTP API.

Всего снято 132 из 187 кадров; 55 мобильных состояний ещё не сняты. Для 34 статических адресов админки зафиксировано сообщение о неподключённом сценарии; некоторые детальные действия доступны через отдельные динамические маршруты, поэтому это не оценка отсутствия всей функции. Все значения визуальной приёмки остаются `pending`. Машиночитаемый [visual-audit.json](visual-audit.json) перечисляет каждый кадр, ошибки и наличие снимка. Доля различающихся пикселей диагностическая: текст, реальные данные и растеризация тоже влияют на неё.

Исправлены компоновка S03/S04, категории и блок создания заказа S06, профиль S08, выбор роли S11 и разделение просмотра/редактирования проекта S39. Выбор города открывается из главного экрана и сохраняется через API. Десктопная компоновка публичных страниц приведена к размерам исходных экспортов. Эти изменения не закрывают полную визуальную приёмку.

Воспроизведение после установки зависимостей, Python Pillow и Chromium:

```bash
python3 scripts/prepare-visual-assets.py --output /tmp/joba-visual-assets
JOBA_VISUAL_ASSETS_DIR=/tmp/joba-visual-assets JOBA_ALL_SCREENS_DIR=/tmp/joba-all-mobile-visual bash scripts/flutter-mobile.sh test test/visual_inventory_test.dart --reporter expanded
JOBA_BROWSER_INVENTORY_DIR=/tmp/joba-all-browser-visual npm run admin:verify-browser
python3 scripts/compare-design.py --surface mobile --captures /tmp/joba-all-mobile-visual --output /tmp/joba-mobile-comparison
python3 scripts/compare-design.py --surface admin --captures /tmp/joba-all-browser-visual --output /tmp/joba-admin-comparison
python3 scripts/compare-design.py --surface public --captures /tmp/joba-all-browser-visual --output /tmp/joba-public-comparison
```

Команда сравнения сохраняет исходный PNG, текущий снимок и абсолютную разницу без изменения масштаба; при несовпадении размеров метрика не вычисляется. Полные результаты остаются в указанном каталоге, отдельные текущие снимки — в `mobile/`. Требуют дальнейшей работы оставшиеся мобильные состояния, каталог/фильтры/карта, неподключённые статические сценарии админки и проверка всех действий. Внешние интеграции, iOS/устройства и нагрузочная проверка в этот прогон не входят.

Текущие кадры после исправлений: [S03](mobile/S03-terms.png), [S04](mobile/S04-onboarding.png), [S06](mobile/S06-home.png), [S08](mobile/S08-contractor.png), [S11 — роль](mobile/S11-roles.png), [S39](mobile/S39-portfolio-project.png). Они используют явно тестовые записи; фотографии взяты из исходных иллюстраций макета только для визуального прогона.

Проверка этого набора изменений: 42 backend-теста, 30 обычных Flutter-тестов, отдельный реальный HTTP-прогон Flutter, анализ без замечаний, Android debug APK и полный функциональный браузерный прогон прошли. Отдельно прошёл опциональный визуальный тест 60 мобильных кадров.
