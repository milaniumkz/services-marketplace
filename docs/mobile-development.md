# JOBA: Flutter-клиент и API

Мобильный клиент находится в `apps/mobile`, Android/iOS runners включены в репозиторий. Это развиваемая реализация клиента, а не подтверждение полного покрытия ТЗ и всех 42 макетов. Сводка незавершённого приведена в конце документа.

## Подключение

Региональные серверы задаются при сборке через `--dart-define=JOBA_KZ_API_URL=...`, `JOBA_RS_API_URL`, `JOBA_RU_API_URL`, `JOBA_BY_API_URL`. В release общий `JOBA_API_URL` служит резервом только для KZ; остальные регионы без собственного URL недоступны. В debug общий адрес допустим для локальной разработки. Клиент добавляет `/api/v1` сам. Указывайте корень регионального API без query, fragment и credentials. Release требует HTTPS; отсутствующий production URL не заменяется демонстрационным сервером.

```bash
npm ci --cache /workspace/.npm
npm run verify
npm run dev:api
bash scripts/flutter-mobile.sh pub get --enforce-lockfile
bash scripts/flutter-mobile.sh run --dart-define=JOBA_API_URL=http://10.0.2.2:3000
```

`10.0.2.2` — адрес хоста для Android Emulator. Для физического устройства задайте адрес доступного ему сервера. В production используйте HTTPS и endpoint соответствующей страны: backend проверяет `JOBA_REGION`. `JOBA_API_URL` не содержит секретов. Auth/register передают выбранную страну; UUID, валюту, состояние и версию объектов возвращает API.

Проверенные инструменты: Flutter 3.35.7 (`adc901062556672b4138e18a4dc62a4be8f4b3c2`), Dart 3.9.2, JDK 21.0.12.1, Android compile SDK 36, NDK 27.0.12077973, Gradle 8.12. Flutter/Android SDK/JDK находятся вне checkout в `/workspace`; они не являются отдельными продуктовыми репозиториями.

`scripts/flutter-mobile.sh` устанавливает рабочие каталоги кэшей, переходит в `apps/mobile` и запускает Flutter. `FLUTTER_ROOT`, `JAVA_HOME`, `ANDROID_HOME` можно задать для собственной машины; скрипт не меняет HOME. На macOS запускайте установленный Flutter напрямую либо задайте эти пути.

## Сессия и запросы

- Оpaque bearer access token, refresh rotation, один параллельный refresh. Токены хранятся в platform secure storage; PIN и ключи биометрии не отправляются серверу.
- Нет перенаправления запросов с credentials. Release URL должен использовать HTTPS.
- При повторе команды после обновления токена сохраняется `Idempotency-Key`. Неоднозначная ошибка сети сохраняет ключ для повторной отправки того же payload в текущем процессе.
- Параллельные одинаковые GET объединяются без сохранения приватных ответов на диск; списки используют серверные cursor и фильтры. Ошибки/пустые состояния не заменяются постановочными записями.
- Logout/отзыв сессии очищает сохранённые токены. Поздний ответ refresh не восстанавливает уже закрытую сессию.
- Входящие mailbox события поступают через authenticated WebSocket с resume sequence. Chat сохраняет введённый текст при событиях, переподключается после восстановления приложения и использует polling как запасной путь. Статус чтения отмечается после показа последних сообщений.

## Локальная защита

PIN 6–8 цифр, PBKDF2-HMAC-SHA256 100000 итераций и случайная соль; вычисление вынесено из UI isolate. Счётчик сохраняется до проверки PIN; после пяти неверных попыток нужен полный вход. Повторное открытие и возвращение после 60 секунд в фоне требуют разблокировки.

Android проверяет hardware-backed Keystore; системная биометрия использует `BiometricPrompt` с CryptoObject и ключом, инвалидируемым при изменении enrollment. На Android 23 доступен PIN при аппаратной защите, биометрический сценарий требует Android 24+. iOS использует Secure Enclave, Keychain `WhenPasscodeSetThisDeviceOnly` для локального замка и `biometryCurrentSet`. Отказ или отсутствие безопасного механизма оставляет вход по номеру и паролю. Это не заменяет серверную проверку личности.

Проверка KDF, лимита попыток и изменения enrollment в Flutter-тестах использует изолированные platform doubles. Работа физических датчиков, passcode/enrollment changes и iOS Keychain на реальном устройстве этими тестами не подтверждена.

## Проверки

На предыдущем этапе: 16 backend тестов, 10 Flutter unit/widget/platform-contract тестов, отдельный реальный HTTP-тест Flutter → Nest/PGlite и Android debug сборка прошли. Анализатор — 0 замечаний. Повторный setup script прошёл на сохранённых SDK/кэшах; чистое восстановление в новой задаче не проверялось.

```bash
npm run mobile:analyze
npm run mobile:test
npm run mobile:verify-api
npm run mobile:build:android
```

`mobile:verify-api` запускает настоящий Nest API с отдельной in-memory PGlite и временными encrypted files, выполняет HTTP-тест Flutter-клиента, останавливает сервер и удаляет файлы. Рабочая БД и внешние провайдеры не используются. Сценарий: register/me/catalog/cities/draft/profile/support/case/privacy/refresh/logout. Обычный `mobile:test` помечает этот тест skipped при отсутствии специального endpoint; отдельная команда выполняет его реально.

Android debug APK: `apps/mobile/build/app/outputs/flutter-apk/app-debug.apk`. Он предназначен для разработки, не является подписанным production релизом. Для iOS нужны macOS/Xcode, `flutter build ios --no-codesign`, затем реальные проверки Keychain/биометрии и provisioning. Сборка iOS в Linux не выполнялась.

В managed cloud Java/Gradle должны использовать существующий HTTPS proxy и доверенный CA. Gradle proxy properties находятся в `/workspace/.gradle/gradle.properties`, не в репозитории. Oracle JDK архив проверен по опубликованному SHA-256; Android tools — по checksum официального repository XML; Gradle distribution SHA-256 закреплён в wrapper properties. TLS verification не отключается.

Подключены к API: регистрация/вход, профиль, собственные/назначенные заказы и поиск, черновик/публикация/редактирование, отклики/выбор/отзыв, начало/завершение/доработка, двусторонние изменения и отмена, приглашения, чаты и вложения, поддержка/recovery, отзывы/голосование, жалобы/апелляции, уведомления/настройки, сессии/пароль/телефон/блокировки, портфолио/фото/порядок/права, verification sessions, legal consents, referral commands, privacy requests/cancel/export, просмотр доступа и продвижений.

История чата получает последние 100 сообщений и загружает ранние отдельно; правки/удаления передаются как обновления, а read события не создают лишних пользовательских уведомлений.

Оригинальные Noto Sans и логотип включены с лицензией; иконки платформ генерируются из того же исходного изображения. Токены цветов, размеров и базовая структура взяты из прототипа. Но полного visual comparison 42 экранов/115 состояний нет: часть отдельных макетов сейчас объединена в общие detail/form экраны. Нельзя объявлять дизайн «1в1».

Помимо подключений провайдеров остаются: полное воспроизведение отдельных экранов/состояний, расширенные геосценарии, обработка восстановления доступа по утверждённой политике, физические/iOS проверки, accessibility и нагрузочные проверки. API/backend production ограничения перечислены в `backend-status.md`.

Payment/ads/Firebase/AV/PDF/legal infrastructure gates остаются действующими. Файлы не становятся clean без проверки, загрузка не даёт verified, просмотр рекламы не выдаёт доступ на клиенте, отсутствие платёжного провайдера не даёт фиктивную успешную покупку. Эти ограничения — действующие ответы API, а не тестовые записи приложения.

## Продолжение реализации 13 октября

Добавлены редактирование отклика и отдельное подтверждение актуальной ревизии заказа; история сообщений по обращению; переход из уведомления к связанному объекту и отметка всех полученных уведомлений; часы тишины с IANA часовым поясом. Профиль исполнителя сохраняет форматы работы, опыт как собственное утверждение, языки, города обслуживания, радиус выезда, доступность и ориентировочную цену в валюте страны. Чужое опубликованное портфолио и галерея доступны через API с проверкой доступа к файлам.

Поиск исключает скрытые материалы, заблокированные пары, неподходящих владельцев и истёкшие заказы до серверной пагинации; точный адрес не передаётся в поисковой выдаче. Это покрыто отдельным тестом границ доступа и перехода между страницами. Полная локализация и соответствие всех экранов макетам ещё проверяются и дорабатываются.

Админку можно проверить командой `npm run admin:verify-browser`. Она запускает собственный временный Vite и настоящий HTTP API с изолированной базой, проверяет служебный MFA-вход, сохранение и валидацию черновика, отказ в самостоятельной публикации и выход. Требуется Chromium; путь задаётся `JOBA_CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`. Тестовые учётные записи существуют только в памяти этого процесса.

Экспорт теперь формируется потоково как ZIP с JSON/CSV и собственными безопасными вложениями, зашифрован на диске и сообщает о готовности в приложении. При ошибке предусмотрены ограниченные повторные попытки; частично записанный архив удаляется. Профиль пользователя поддерживает языки общения, выбор настроенной роли и загрузку/удаление аватара.

Реальные widget-тесты проверяют четыре языка, отсутствие переполнения выбора страны и сохранение введённых данных при смене языка.

Android debug APK после локализации собран, реальный HTTP-тест Flutter прошёл; всего 22 Flutter-теста проходят, анализатор — 0 замечаний. Полное визуальное сравнение всех экранов и локализация некоторых динамических серверных сообщений ещё продолжаются.

Дополнительно проверены повтор загрузки после потери ответа без второго файла, защита от повтора команды под другим аккаунтом, загрузка аватара через реальный HTTP, изменение интерфейса четырёх локалей без очистки введённых полей. Экран входа приближен к S02 по фону, полям и подписям; полная визуальная приёмка всех экранов ещё не выполнена.

Экран документов показывает принятие текущей опубликованной версии и позволяет отозвать согласие. Продолжение закрывается, если опубликованные условия или политика не приняты; поддержка остаётся доступной. Это проверено отдельным widget-тестом принятия и отзыва.

Исходные векторные иконки прототипа перенесены в Flutter. По S01/S02 проверены реальные web-снимки: уточнены интервалы букв, цвета, высоты полей и отступы. Это сверка двух экранов, а не всех 42/115. История опубликованных версий и пауза профиля подключены к API. Фотографии загружают preview, а по нажатию открывают полноразмерное изображение с масштабированием.

Экспорт на Android/iOS сначала скачивается потоком в временный каталог приложения, затем передаётся системному выбору файла; временная копия удаляется после результата. Реальный HTTP-тест теперь ждёт завершения worker и получает ZIP через этот потоковый API.

Цены форматируются по выбранному языку и валюте, без потери целых minor units даже для больших сумм; проверены разделители и дробные значения.

S40.new подключён к API: выбор темы, связанного заказа текущей роли, вопрос, до 10 вложений с назначением `chat`. Форма сохраняет текст и список файлов после отказа сервера; во время отправки редактирование вложений закрыто. Сервер создаёт обращение и первое сообщение в одной транзакции с идемпотентностью; чужие/зарубежные заказы и непроверенные файлы не принимаются. Физический системный picker и production-сканер ещё требуют проверки с интеграциями.

S39.lightbox получает реальные ID фотографий проекта: счётчик, предыдущая/следующая, увеличение/уменьшение и закрытие работают. Загружается оригинал активного фото; масштаб сбрасывается при переключении. После смены или завершения сессии изображение, название проекта и счётчик скрываются. Индивидуальных подписей к каждой фотографии в текущем API нет; показывается настоящее название проекта, без вымышленных описаний из демонстрации. Это и остальные визуальные отличия остаются частью незавершённой приёмки.

S03.documents: отдельный каталог опубликованных правовых документов доступен из приватности и раздела о приложении. Запрос `/legal/documents` использует выбранные страну и язык без требования сессии. Читатель показывает содержание выбранного неизменяемого документа, его версию и дату; тот же читатель используется при регистрации. Переход не принимает согласие автоматически. Тест проверяет регион/язык, отсутствие Authorization и фактическое содержание выбранной записи.

S30.restricted: экран ограничений загружает действующие меры через `/me/restrictions`. Поддержка, приватность, действующие заказы и просмотр доступного дела работают отдельно от новых бизнес-действий. Апелляция открывается только для доступного актуального решения; перед открытием формы перечитывается само дело. Срок показан с точным временем и явным UTC. Событие `sanction.created` обновляет статус аккаунта; при обновлении экрана ограничения перечитываются. Отсутствие подробностей не подменяется вымышленной причиной или датой.

S02/S02.register: имя заполняется на отдельном шаге профиля, а регистрация отправляет телефон, пароль, страну и язык. Добавлены пояснения к логину/паролю и исходные подписи, исправлены отступы, положение иконок и заголовка. Несовпадающие пароли не отправляются в API; отказ сервера сохраняет все три поля. Состояние ошибочного входа снимается после настоящей отправки формы в изолированном сценарии, а не статичной картинкой.

S30.appeal/S30.appeal-sent: отдельная форма апелляции показывает выбранное решение, принимает объяснение 10–3000 символов и до 10 материалов `chat`. Неуспешная отправка сохраняет текст и файлы; при конфликте версии требуется перечитать решение перед повтором. Сообщение об отправке появляется только после ответа со статусом `appealed`; кнопка открывает «Мои обращения». Текст и вложения доступны в карточке своего дела. Материалы не отправляются как новые сообщения и не запускают повторную проверку словарём.

S17.success/S21.sent/S28.sent: отдельные подтверждения читают заказ/отклик из API после успешной команды. Статусы модерации, закрытый заказ и скрытие/публикация отзыва учитываются при выборе текста. Если собственный отзыв отсутствует, экран не утверждает, что он сохранён. Переход из отклика в заказ использует `order_id`, а не ID отклика. Кнопки открывают список откликов, заказы или подходящие работы; штатные публикация и отправка отзыва теперь ведут на эти экраны. Тест проверяет положительные и изменённые серверные состояния и реальные аргументы переходов.

S12.pending/S38.pending: отправка изменений профиля и проекта открывает отдельный экран ожидания. Повторное чтение API учитывает результат проверки. Старую версию экран называет видимой только при `public_visible=true`; статус черновика и `public_status` этого не доказывают. GET собственного профиля и проверка связанного профиля для проекта выполняются SQL с ограничением владельца/страны, без чтения всех профилей страны.

S34.export/S34.export-pending: отдельные шаги запроса, повторного ввода текущего пароля и подготовки связаны с собственным заданием экспорта. Статус перечитывается при событиях и повторном открытии; готовый архив доступен только при серверном `download_available=true`. Подтверждение сохранения выдаётся после результата существующего потокового системного сохранения. Истёкший архив предлагает новый запрос. Обработчик JSON-ошибок отличает ошибки повторного ввода пароля от истечения access token; `REAUTH_REQUIRED` сохраняет сессию и поля формы. Проверено настоящим HTTP из Flutter. Нижние панели форм, профиля, подтверждения публикации, приглашения, языка и апелляции используют отступ 4 над системной областью и верхнюю границу по макету.

Никакая покупка, отмена подписки или рекламная награда не подтверждается локальным нажатием.
