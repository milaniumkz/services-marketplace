# Мобильные платежи и возвраты

Добавлен маршрут `refunds` из профиля обеих ролей. Заказчику не предлагается подписка: список показывает только его реальные платежи, включая отдельное продвижение, если оно покупалось.

`RefundsScreen` читает `/billing/refundable-payments` и `/billing/refund-requests` с cursor-пагинацией и обновлением. Карточка платежа показывает серверный доступный и зарезервированный остаток. `RefundEditor` создаёт полную/частичную заявку по `payment_id`, точной сумме в минимальных единицах и причине. Отправка требует явного ознакомления с возможным влиянием возврата на доступ. Согласование не отображается как возврат денег.

Сумма разбирается без double, с максимумом двух десятичных знаков и проверкой безопасного целого. Остаток проверяется на клиенте и окончательно сервером. При неизвестном результате отправки поля фиксируются: повтор использует тот же payload и сохранённый `JobaApi` idempotency key. Можно вернуться и проверить историю. При подтверждённой ошибке ввода данные сохраняются для исправления.

В истории есть деталь заявки, правдивые статусы, переход в поддержку и отмена только `requested`. Отмена требует подтверждения, передаёт `expected_version`; конфликт не подменяет серверный результат, предусмотрено обновление истории. Неизвестные и старые статусы/суммы показываются как требующие уточнения.

Интерфейс использует общие дизайн-компоненты и переводы действующих языков ru/kk/sr/be. Новые страницы не имеют исходных PNG: их нельзя объявить принятыми 1:1. Добавлены в supplementary-реестр; оригинальные 191 кадр и их pending не меняются.

Проверки: `test/refunds_test.dart` — точные суммы/границы, mobile viewport, пагинация, потерянный ответ с тем же ключом, конфликт отмены/обновление, полностью зарезервированный платёж. Данные MockClient используются только в тестах. Рабочий экран использует обычный `JobaApi`, без fixture или fallback-платежей. Снимки получаются через `JOBA_SCREENSHOT_DIR` и явно содержат изолированные тестовые записи.

Реальная оплата, отправка/подтверждение банковского возврата, много процессный PostgreSQL и визуальная приёмка новых экранов остаются отдельными работами. Изменения не развёрнуты на сервере.

Проверка итерации: полный Flutter-набор — 95 passed, 2 skipped (опциональная визуальная инвентаризация); анализ — 0 issues. После добавления отображения ошибок возвратов прошли 7 связанных тестов возвратов/локализации. Четыре новых кадра находятся в `docs/design/review/mobile/refund-*.png`; исходного эталона для них нет.
