# Яндекс и Google в приложении

Android использует один закреплённый баннер высотой 50 dp над нижним меню.
Все 100 подходящих страниц перечислены в [PAGES.md](PAGES.md), включая формы,
переписку, портфолио и настройки. Оплата, вход/PIN, полноэкранная камера
и открытая клавиатура исключены.
Переключение вкладок сохраняет тот же экземпляр баннера.

Сеть закреплена за страницей. Полный перечень: [100 страниц и исключения](PAGES.md).
50 страниц используют Яндекс, 50 — Google. Обычные баннеры не переключаются
на другую сеть при ошибке: незаполненное место скрывается. При смене страницы
с той же сетью экземпляр баннера сохраняется; при переходе на другую сеть
старый баннер освобождается до загрузки нового.
В браузере используются РСЯ и AdSense (`ca-pub-5590941579295248`, слот `8113418919`); нативные AdMob ID
в браузер не передаются для показа.

В админке → «Подписка и реклама» → настройки рекламы:
- «Включить обычные баннеры» управляет всеми обычными баннерами;
- «Включить Google AdMob в Android» управляет только Google;
- поле «Баннер AdMob Android» содержит ID блока, с `/`, а не ID приложения с `~`.

Используемые Android ID:
- Google приложение: `ca-app-pub-5590941579295248~1739074102` (AndroidManifest);
- Google баннер: `ca-app-pub-5590941579295248/9567708649`;
- Яндекс баннер: `R-M-20254161-1`.

Подписка за рекламу в Android использует случайную первую сеть (Яндекс/AdMob,
50/50 из доступных) и одну попытку резервной сети при ошибке загрузки. При
закрытии уже загруженного ролика следующий автоматически не открывается.
Только завершённый ролик засчитывается в общий набор выбранной услуги; награда
выдаётся один раз после набора необходимого количества. Google AdMob Rewarded:
`ca-app-pub-5590941579295248/6068875357`. В браузере Rewarded остаётся у Яндекса:
для Google Rewarded Web нужен отдельный блок Google Ad Manager, предоставленный
AdSense-баннер для этого не подходит.
Для iOS нужны отдельные ID; Android-блоки на iOS не используются.

Изменение добавляет нативный SDK Google и требует обновления установленного
Android-приложения. Обновление сервера не добавляет SDK в ранее установленный APK.
По последнему указанию владельца APK в рамках этой задачи не собирается.
Проверки используют моки SDK и не создают рекламных показов.
