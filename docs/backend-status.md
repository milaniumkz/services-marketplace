# Статус реализации JOBA

Это отчет о текущем коде ветки, а не утверждение готовности полного первого релиза ТЗ v1.1. Пользователь подтвердил использование предложенных параметров как исходных; реальные платежи, рекламную сеть, Firebase и сервер предоставит позднее.

## Реализованные серверные сценарии

- Регистрация/вход номером и паролем без SMS/email, E.164/country checks, Argon2id, смена телефона/пароля с reauth, ротация и отзыв сессий.
- Доменные роли, object ownership/country scope, версия объекта, idempotency, отдельный staff login с MFA.
- Черновик и публикация заказа, актуальность ревизии отклика, атомарный выбор с assignment snapshot, начало, завершение/доработки, двусторонняя отмена и поправки, приглашения.
- Контекстные чаты, sequence/client-message dedupe, ограниченное редактирование/tombstones, read/delivered acknowledgements, durable notifications и WebSocket events.
- Двусторонние completed-order отзывы, double-blind публикация и окно исправления; отдельные likes/dislikes и organic score.
- Профили и портфолио с clean-upload gates; закрытые файлы, AES-GCM, image sanitization, scoped одноразовые ссылки; ручная ID-проверка с отдельной ролью.
- Поддержка/ограниченный pre-login recovery chat, assignment/status commands, отдельные internal notes. Автоматического сброса по неподтверждённому номеру нет.
- Модерация по версионированным словарям без пользовательского regex, quarantine/case/temporary hold, expiry без автоматического постоянного blacklist; ручные решения и апелляции.
- Append-only audit/финансовые записи, independent ad flags, админские price/config drafts и двойное подтверждение, promo timezone boundary, finite compensation grants.
- Referral attribution/qualification/redeem с бюджетом; boost capacity/reservation/verified purchase/admin provenance и eligibility/expiry.
- Outbox worker, retry/dead-letter, quiet hours и реальные provider send outcomes; потоковая сборка зашифрованного ZIP с JSON/CSV и собственными вложениями вне очереди API, reauth deletion request и остановка удаления при отсутствии утверждённого retention policy.

## Проверенное

Автоматические тесты прошли на этапе проверки доменной реализации. Дополнительно прошёл HTTP/WebSocket smoke на отдельном PostgreSQL 16: auth/envelopes, ETag/304, binary upload, закрытые scanner/payment gates, выбор исполнителя и scoped событие.

Изолированный performance check: 5000 синтетических заказов, 100 последовательных warmed запросов по 20 записей, PostgreSQL 16; p50 2,69 мс, p95 10,49 мс, max 21,95 мс. Это время доменного вызова, без HTTP/сети, параллельной нагрузки, мобильного устройства и внешних API. Оно не является обещанием моментального production ответа.

Сборки API/admin/client/public прошли. Docker backend собран с закреплённым Node image и CA-бандлом TLS-прокси через build secret, запущен с временным PostgreSQL; health/bootstrap HTTP прошли.

## Что ещё требует завершения/подтверждения

- Реальные adapters/credentials и end-to-end provider проверки: платежи, рекламная SSV, Firebase и поддерживаемая база сигнатур AV. По умолчанию они не включены и не выдают фиктивный успех.
- Утверждённые тексты/legal/country/retention flows и региональная инфраструктура. Локальная PGlite имеет логическую country ACL, но не подтверждает физическую изоляцию четырёх регионов.
- Production hardening: отдельные migration/runtime DB roles, полноценные schema/DTO/FK contracts, нагрузочная/penetration проверка, backup/restore, encrypted-volume/key rotation, exhaustive retention/delete по вложениям и legal holds.
- Расширение OpenAPI из текущего HTTP-инвентаря до строгих DTO всех команд; часть схем пока permissive.
- Продвинутые геофильтры, provider coupons/discount redemption и полные финансовые/аналитические отчеты; не заменять их демонстрационными значениями.
- Flutter-клиент теперь подключён к API, добавлены native runners, secure storage/PIN/биометрические ключи и Android debug сборка. Полное покрытие UI и состояний, полная сверка четырёх локалей, visual comparison и physical/iOS проверки остаются незавершёнными: [статус мобильной реализации](mobile-development.md).

Репозиторий не следует объявлять полностью соответствующим ТЗ или готовым к production до закрытия этих пунктов. Пользовательские данные обычного API создаются запросами и сохраняются; тестовые записи изолированы от рабочей базы.

## Текущие дополнения к реализации

- Rate limit хранится в PostgreSQL с HMAC-ключами; счётчики не откатываются при отказе бизнес-команды. Проверены общая квота нескольких процессов, атомарная повторная команда и гонка refresh на отдельном PostgreSQL 16.
- Staff bootstrap выполняется отдельной отключённой по умолчанию CLI. TOTP-секрет шифруется с привязкой к ID; обычный вход сотрудника закрыт.
- Обработка файлов и экспорт выполняются вне очереди запросов. Нативный Poppler преобразует PDF в новый документ из растровых страниц; исходные активные объекты не копируются. Реальная база сигнатур AV на сервере ещё необходима.
- Админские карточки аккаунтов/заказов/проектов/проверок, решения по документам, раскрытие телефона с аудитом, настройки лимитов и редактор legal drafts подключены к API. Это не означает завершения всех 22 экранов и состояний макета.
- Публичная правовая страница загружает только опубликованные документы выбранной страны/локали. Чат поддержки сохраняет capability в sessionStorage текущей вкладки на 24 часа; повторная команда использует тот же ключ идемпотентности.

Проверка текущего кода: 27 backend-тестов, 20 Flutter-тестов (HTTP integration отдельно), анализ Flutter без замечаний, Android debug APK. Браузерная проверка использует настоящий изолированный HTTP API и проверяет MFA, потерю ответа без дубля, проверку конфигурации, запрет самостоятельной публикации, решение по заявке, аудит телефона, настройки, legal drafts, публичные документы и сохранение переписки после обновления. Эти проверки не заменяют iOS/physical/load и полного визуального сравнения.

После дополнений серверный Docker образ успешно собран с Poppler/ClamAV; внутри образа прошла проверка реального PDF-парсера (две страницы, сохранение геометрии, удаление активных объектов). Проверка антивирусных сигнатур этим не подтверждается.

Публикация заказа/профиля, отклик и выбор исполнителя проверяют последнее согласие на опубликованные условия и политику для языка аккаунта; отзыв блокирует новые бизнес-команды и сохраняет доступ к приватности и поддержке.

Опубликованные профили и проекты сохраняют одобренную версию при редактировании: черновик закрыт, отклонение не удаляет публикацию, одобрение архивирует предыдущую версию. История доступна владельцу без подписки. Пауза профиля применяется сразу; возобновление проверяет доступ и верификацию. Публичное портфолио учитывает заданный порядок; связь с completed проверяет assignment исполнителя и не раскрывает клиенту чужой order ID.

Изображения проходят проверку фактического формата, исправление EXIF-ориентации и удаление metadata; сервер создаёт защищённый preview до 960 px. Preview и оригинал проверяют права на родительский файл. Экспорт скачивается потоком через контроллер; тест блокирует попытку буферизации архива целиком. Эти изменения не закрывают оставшиеся геопоиск, операционные разделы и полную визуальную приёмку.

Раздел подписки/рекламы теперь имеет независимые переключатели и типизированные поля вместо JSON-редактора. Баннерная сеть/размещение проверяются провайдером до публикации. Кредиты ограничены изменяющими действиями; поиск использует временный доступ, срок кредитов задаётся явно. Сводка страны показывает реальные счета/права/сессии без PII.

Экран проверки документов получает разрешённые типы из текущей опубликованной региональной политики, показывает выбор вместо произвольного ввода и предлагает начать только после согласия. API проверяет актуальный hash правового документа; отзыв согласия или новая редакция требуют нового согласия. Изолированный тест покрывает отсутствие политики, ограничение типов, последовательность согласий и смену hash. Проверка всех сторон документа и полного визуального соответствия этого сценария ещё не завершена.
