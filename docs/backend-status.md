# Статус реализации JOBA

Это отчет о текущем коде ветки, а не утверждение готовности полного первого релиза ТЗ v1.1. Пользователь подтвердил использование предложенных параметров как исходных; реальные платежи, рекламную сеть, Firebase и сервер предоставит позднее.

## Реализованные серверные сценарии

- Регистрация/вход номером и паролем без SMS/email, E.164/country checks, Argon2id, смена телефона/пароля с reauth, ротация и отзыв сессий.
- Доменные роли, object ownership/country scope, версия объекта, idempotency, отдельный staff login с MFA.
- Черновик и публикация заказа, актуальность ревизии отклика, атомарный выбор с assignment snapshot, начало, завершение/доработки, двусторонняя отмена и поправки, приглашения.
- Контекстные чаты, sequence/client-message dedupe, ограниченное редактирование/tombstones, read/delivered acknowledgements, durable notifications и WebSocket events.
- Двусторонние completed-order отзывы, double-blind публикация и окно исправления; отдельные likes/dislikes и organic score.
- Профили и портфолио с clean-upload gates; закрытые файлы, AES-GCM, image sanitization, scoped одноразовые ссылки; ручная ID-проверка с отдельной ролью.
- Поддержка/ограниченный pre-login recovery chat, assignment/status commands, отдельные internal notes. Автоматического сброса по неподтверждённому номеру нет.
- Модерация по версионированным словарям без пользовательского regex, quarantine/case/temporary hold, expiry без автоматического постоянного blacklist; ручные решения и апелляции.
- Append-only audit/финансовые записи, independent ad flags, админские price/config drafts и двойное подтверждение, promo timezone boundary, finite compensation grants.
- Referral attribution/qualification/redeem с бюджетом; boost capacity/reservation/verified purchase/admin provenance и eligibility/expiry.
- Outbox worker, retry/dead-letter, quiet hours и реальные provider send outcomes; потоковая сборка зашифрованного ZIP с JSON/CSV и собственными вложениями вне очереди API, reauth deletion request и остановка удаления при отсутствии утверждённого retention policy.

## Проверенное

Автоматические тесты прошли на этапе проверки доменной реализации. Дополнительно прошёл HTTP/WebSocket smoke на отдельном PostgreSQL 16: auth/envelopes, ETag/304, binary upload, закрытые scanner/payment gates, выбор исполнителя и scoped событие.

Изолированный performance check: 5000 синтетических заказов, 100 последовательных warmed запросов по 20 записей, PostgreSQL 16; p50 2,69 мс, p95 10,49 мс, max 21,95 мс. Это время доменного вызова, без HTTP/сети, параллельной нагрузки, мобильного устройства и внешних API. Оно не является обещанием моментального production ответа.

Сборки API/admin/client/public прошли. Docker backend собран с закреплённым Node image и CA-бандлом TLS-прокси через build secret, запущен с временным PostgreSQL; health/bootstrap HTTP прошли.

## Что ещё требует завершения/подтверждения

- Реальные adapters/credentials и end-to-end provider проверки: платежи, рекламная SSV, Firebase и поддерживаемая база сигнатур AV. По умолчанию они не включены и не выдают фиктивный успех.
- Утверждённые тексты/legal/country/retention flows и региональная инфраструктура. Локальная PGlite имеет логическую country ACL, но не подтверждает физическую изоляцию четырёх регионов.
- Production hardening: отдельные migration/runtime DB roles, полноценные schema/DTO/FK contracts, нагрузочная/penetration проверка, backup/restore, encrypted-volume/key rotation, exhaustive retention/delete по вложениям и legal holds.
- Расширение OpenAPI из текущего HTTP-инвентаря до строгих DTO всех команд; часть схем пока permissive.
- Продвинутые геофильтры, provider coupons/discount redemption и полные финансовые/аналитические отчеты; не заменять их демонстрационными значениями.
- Flutter-клиент теперь подключён к API, добавлены native runners, secure storage/PIN/биометрические ключи и Android debug сборка. Полное покрытие UI и состояний, полная сверка четырёх локалей, visual comparison и physical/iOS проверки остаются незавершёнными: [статус мобильной реализации](mobile-development.md).

Репозиторий не следует объявлять полностью соответствующим ТЗ или готовым к production до закрытия этих пунктов. Пользовательские данные обычного API создаются запросами и сохраняются; тестовые записи изолированы от рабочей базы.

## Текущие дополнения к реализации

- Rate limit хранится в PostgreSQL с HMAC-ключами; счётчики не откатываются при отказе бизнес-команды. Проверены общая квота нескольких процессов, атомарная повторная команда и гонка refresh на отдельном PostgreSQL 16.
- Staff bootstrap выполняется отдельной отключённой по умолчанию CLI. TOTP-секрет шифруется с привязкой к ID; обычный вход сотрудника закрыт.
- Обработка файлов и экспорт выполняются вне очереди запросов. Нативный Poppler преобразует PDF в новый документ из растровых страниц; исходные активные объекты не копируются. Реальная база сигнатур AV на сервере ещё необходима.
- Админские карточки аккаунтов/заказов/проектов/проверок, решения по документам, раскрытие телефона с аудитом, настройки лимитов и редактор legal drafts подключены к API. Это не означает завершения всех 22 экранов и состояний макета.
- Публичная правовая страница загружает только опубликованные документы выбранной страны/локали. Чат поддержки сохраняет capability в sessionStorage текущей вкладки на 24 часа; повторная команда использует тот же ключ идемпотентности.

Проверка текущего кода: 43 backend-теста, 31 Flutter-тест (HTTP integration отдельно), анализ Flutter без замечаний, Android debug APK. Браузерная проверка использует настоящий изолированный HTTP API и проверяет MFA, потерю ответа без дубля, проверку конфигурации, запрет самостоятельной публикации, решение по заявке, аудит телефона, настройки, legal drafts, публичные документы и сохранение переписки после обновления. Эти проверки не заменяют iOS/physical/load и полного визуального сравнения.

После дополнений серверный Docker образ успешно собран с Poppler/ClamAV; внутри образа прошла проверка реального PDF-парсера (две страницы, сохранение геометрии, удаление активных объектов). Проверка антивирусных сигнатур этим не подтверждается.

Публикация заказа/профиля, отклик и выбор исполнителя проверяют последнее согласие на опубликованные условия и политику для языка аккаунта; отзыв блокирует новые бизнес-команды и сохраняет доступ к приватности и поддержке.

Опубликованные профили и проекты сохраняют одобренную версию при редактировании: черновик закрыт, отклонение не удаляет публикацию, одобрение архивирует предыдущую версию. История доступна владельцу без подписки. Пауза профиля применяется сразу; возобновление проверяет доступ и верификацию. Публичное портфолио учитывает заданный порядок; связь с completed проверяет assignment исполнителя и не раскрывает клиенту чужой order ID.

Изображения проходят проверку фактического формата, исправление EXIF-ориентации и удаление metadata; сервер создаёт защищённый preview до 960 px. Preview и оригинал проверяют права на родительский файл. Экспорт скачивается потоком через контроллер; тест блокирует попытку буферизации архива целиком. Эти изменения не закрывают оставшиеся геопоиск, операционные разделы и полную визуальную приёмку.

Раздел подписки/рекламы теперь имеет независимые переключатели и типизированные поля вместо JSON-редактора. Баннерная сеть/размещение проверяются провайдером до публикации. Кредиты ограничены изменяющими действиями; поиск использует временный доступ, срок кредитов задаётся явно. Сводка страны показывает реальные счета/права/сессии без PII.

Экран проверки документов получает разрешённые типы из текущей опубликованной региональной политики, показывает выбор вместо произвольного ввода и предлагает начать только после согласия. API проверяет актуальный hash правового документа; отзыв согласия или новая редакция требуют нового согласия. Изолированный тест покрывает отсутствие политики, ограничение типов, последовательность согласий и смену hash. Проверка всех сторон документа и полного визуального соответствия этого сценария ещё не завершена.

Сверка дизайна: реестр `docs/design/screen-audit.json` содержит 187 кадров и 2449 контролов из исходных ZIP. Все 42 основных mobile route сопоставлены по исходному коду; визуальная приёмка каждого кадра остаётся отдельной незавершённой проверкой. Добавлены реальные SQL-счётчики аккаунта до пагинации, публичные имя/аватар/рейтинг исполнителя без телефона, разделы заказов и выбор completed-заказа без ограничения первой сотней. Приглашение/отклик/выбор/завершение пока требуют дальнейшей полной проверки сценариев из ТЗ.

Часть мобильных экранов переработана по структуре макета: главные обеих ролей, профиль, первичный профиль, безопасность/сессии, настройки/язык/страна, создание/предпросмотр, выбор исполнителя, результат, отмена и оценка. Подтверждения привязаны к версиям заказа/отклика. Открытый спор и карантин блокируют автоматическую публикацию отзывов; опубликованные собственные отзывы доступны без подписки. Даты календарного диапазона преобразуются в UTC с IANA-зоной страны и учётом DST. Обновлённая сборка API/admin/client/public, браузерные сценарии, реальный Flutter HTTP-сценарий и Android debug APK проходят. Это не завершение всех экранов/состояний и не подтверждение готовности к коммерческому запуску.

Операционные экраны админки: dashboard отображает действительные счётчики и дневной ряд с общей UTC-границей периода; экспорт JSON содержит те же данные. Security показывает сокращённые IP без token/session metadata. Jobs отображает реальные состояния и допускает только аудируемый повтор подходящих задач с expected_version, проверкой адаптера и запретом повтора активной обработки. Шапка поддерживает поиск в пределах роли/страны и собственные уведомления, демонстрационные номера страниц убраны. Country control имеет независимое подтверждение: registration_enabled и stop_new_business реально проверяются API; безопасное завершение существующего assignment сохраняется. Попытка stop/cancel конфигурации страны не может обойти второе подтверждение. Коммерческие launch approvals этим не заменяются.

Расширенный браузерный тест проверяет период/экспорт, поиск, уведомления, security, job retry, форму country control и запрет публикации автором. Полный визуальный статус по всем 22 admin roots и их states остаётся незавершённым; остальные конфигурационные редакторы и операционные сценарии требуют продолжения реализации/сверки.

Приглашения: проверяются обе стороны и доступ без списания action credit, 72 часа/10 в сутки в runtime settings, активная пара, текущая ревизия и срок заказа. Пользовательские жалобы принимаются только на видимый объект своей страны или объект существующей работы/чата, фиксируют версию и хеш; приватны для автора и уполномоченных сотрудников, включая список дел, сообщения, вложения и privacy export. Решения модерации работают с зафиксированной версией: скрывают или восстанавливают материал, сохраняют состояние текущей работы и снимают только связанный временный hold. Апелляцию рассматривает другой senior moderator; приватные сведения заявителя не попадают в уведомление субъекта.

На отдельном PostgreSQL 16 прошла расширенная проверка двух экземпляров API: уникальная активная пара приглашения, суточный лимит при конкурирующих заказах, сохранение action credits и единственное открытое дело. Это проверка конкретных гонок, а не нагрузочная приёмка всего приложения. Приглашения, разделы дел и их счётчики используют scoped SQL до пагинации.

`/health` больше не возвращает постоянный demo-ответ: успешный ответ требует инициализации базы и выполнения SELECT 1. При недоступной базе возвращается 503; режим показывает development/production. Проверка отказа использует отдельную in-memory базу.

## Региональные подключения и ресурсы бренда

Мобильный клиент выбирает региональный API до восстановления сессии, сохраняет страну и язык отдельно и не переносит токены между регионами. A19 подключён к реальным загрузкам PNG, кадрированию, маскам и списку версий. Независимое подтверждение владельцем бренда и генерация сотрудником release создают зашифрованный ZIP: 18 iOS PNG, Android launcher/adaptive ресурсы пяти плотностей, Google Play PNG и manifest с SHA256. Генерация ресурсов не подтверждает сборку или публикацию приложения.

Проверка текущей версии после изменений: 43 backend-теста, 31 Flutter-тест, отдельный реальный HTTP-сценарий Flutter, анализ без замечаний и Android debug APK. Браузерный сценарий проверяет полный цикл A19 и фактическое скрытие материала по делу. Выбор языка без опубликованного перевода больше не обходит обязательные согласия: клиент показывает опубликованный региональный документ. Полная поэкранная приёмка всех макетов остаётся открытой.

Проверка документа: новые политики требуют явного набора сторон/страниц для каждого типа (до четырёх, без сбора всех страниц паспорта по умолчанию). Заявка сохраняет этот набор; API проверяет количество, уникальность, clean-статус и привязку файлов, актуальность политики и согласия при отправке. Клиент последовательно запрашивает необходимые страницы и сохраняет уже загруженные файлы при отмене выбора или ошибке. Старые политики без набора страниц используют прежний одиночный документ; их необходимо переутвердить с явными требованиями. Полная визуальная сверка проверки документа ещё открыта.

S13: выделен нативный экран выбора документа и загрузки утверждённых страниц, ожидания, отказа и результата. Решение verification reviewer создаёт durable notification и событие для приложения; пользовательский DTO исключает reviewer ID и ссылки на закрытые документы. Повтор отправки после ошибки сохраняет страницы без повторного выбора. Тест проверяет действующие кнопки загрузки, согласия, условий и повторной отправки. Полная визуальная приёмка всех состояний остаётся открытой.

S37: экран приглашений показывает код, реальные количества pending/qualified и условия действующих программ без обещания демонстрационной награды обоим участникам. Правила и ввод кода подключены к API; копирование и системный share используют текущий код. Проверки Flutter дополнены обновлением открытого S13, отзывом согласия и изоляцией страниц при смене типа документа. Native share Android скомпилирован; iOS-код требует отдельной macOS/device проверки.

Профиль мастера S08 теперь получает реальные счётчики completed-заказов и опубликованных проектов, дату действующей проверки и сумму в minor units. Добавлен отдельный публичный endpoint проекта с проверкой страны, подписки, блокировок и статуса публикации; собственный проект открывается для просмотра, редактирование — отдельно. Согласие S03 требует двух явных подтверждений и возрастной декларации для опубликованных условий с `minimum_age=18`; маркетинговые настройки сохраняются отдельно, новая редакция сбрасывает подтверждения. Это не проверка возраста по документу.

Повторяемая визуальная сверка и её незавершённые пункты: [отчёт](design/review/README.md). Наличие снимка, теста или успешной сборки не подтверждает соответствие каждого экрана макету.

Каталог исполнителей теперь фильтрует формат услуги, начальную цену в minor units и средний опубликованный рейтинг до курсорной пагинации. Учитываются дополнительные города обслуживания; дистанционная услуга ищется в пределах страны независимо от города. Скрытые отзывы и отзывы другой страны исключаются. Добавлен формат `workshop` («У исполнителя») в редактор профиля. Диапазон цены исключает договорные цены; радиус поиска по координатам пока не реализован.

2026-10-15: добавлены региональные сводки `/admin/users/{id}/orders`, `/cases`, `/support-threads`, `/decisions`. Заказы включают обе роли; частные адреса, сообщения и доказательства в сводки не входят. История служебных решений использует неизменяемый audit и хронологическую пагинацию по времени/UUID. Курсоры связаны с выбранным аккаунтом и типом сводки. Список пользователей теперь фильтрует служебные аккаунты до SQL-пагинации. События конкретного пользователя возвращают маску IP и требуют непустую служебную причину; полный IP и family сессии исключены.

Карточка задачи `/admin/jobs/{id}` возвращает безопасные метаданные без приватного payload. `scheduled=true` выбирает сохранённые будущие повторы до пагинации; это не редактор cron. Карточка и список используют действующий version-check и audit повтора, а обработка остаётся за worker. Полная временная выдача IP, управление устройствами из карточки, редактор расписаний и история попыток ещё не реализованы. Проверка: 43 backend-теста и полный браузерный сценарий с новыми вкладками/фильтром заказов/карточкой задачи/выходом прошли; мобильный код в этом этапе не менялся.

2026-10-15: `POST /support/threads` поддерживает необязательные `topic`, `order_id`, `text`, `upload_ids`. Обращение и первое сообщение сохраняются атомарно; старый клиент с одним `subject` поддерживается. Привязка заказа разрешена только заказчику или назначенному исполнителю в той же стране. Вложения должны быть собственными проверенными файлами `chat`; при вложениях требуется текст. Командная идемпотентность предотвращает повторные обращения/сообщения. Прошли 44 backend-теста и реальный Flutter HTTP-сценарий с составлением обращения и чтением его первого сообщения. Внешние провайдеры и производственная нагрузка этим не проверяются.

`GET /me/restrictions` возвращает только текущие ограничения аккаунта в стране сессии. Истёкшие и снятые меры, чужие пользователи и регионы исключены в SQL. - Scheduled → sending → completed с cutoff/cursor, порциями по 100, уникальными получателями и уведомлениями. Отмена останавливает оставшуюся очередь; deadline истекает без поздней отправки. Completed содержит реальные итоговые состояния, включая suppressed/expired/dead_letter.
