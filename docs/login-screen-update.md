# S02: вход, ошибка и ограничение попыток

Итерация после `4fbc7d1`. Обновлены обычный вход и его состояние ошибки; совместимые изменения применяются к форме регистрации. Заказчик остаётся бесплатным; интеграции и сервер не включались.

## Интерфейс и ввод

Уточнены рамки, высоты и отступы полей, положение текста и кнопки просмотра пароля. На клавиатуре телефон использует «Далее», последнее поле — «Готово» с отправкой формы. Телефон проверяется на международный формат рядом с полем; внешний пробел убирается перед отправкой, содержимое пароля не обрезается. Добавлены подсказки для менеджеров паролей, отдельные для существующего/нового пароля; системное сохранение завершается после успешной подготовки входа, уход из незавершённой формы отменяет контекст автозаполнения. Реальные менеджеры паролей и устройства требуют отдельного прогона.

Во время запроса поля/повтор/переходы в регистрацию и восстановление/возврат назад заблокированы. После ответа они доступны снова; потерянные и ошибочные ответы не стирают допустимый ввод. Изменения локализованы для ru/kk/sr/be.

## Защита новой сессии

Перед входом/регистрацией интерфейс выключает постоянное хранение токенов. Успешный вход переводит к настройке локальной защиты; PIN включает сохранение сессии, выбор полного пароля оставляет её в памяти.

Если выдача токенов прошла, а загрузка профиля/согласование языка не завершились, незавершённая локальная сессия очищается. Это не объявляется подтверждённым отзывом серверной семьи: её срок определяется сервером. Для уже созданного аккаунта показано предложение войти, телефон перенесён в форму входа; повторная регистрация не отправляется автоматически.

## S02.error

Ошибки credentials и ограничение попыток получили заголовок «Попробуйте ещё раз», сообщение у поля пароля, соответствующую рамку и отдельную помощь. Стрелка назад из ошибки сначала возвращает к той же форме входа с сохранёнными значениями и скрытым паролем; следующий возврат открывает предыдущее состояние.

Обратный отсчёт берётся из `error.details.retry_after_seconds`. На сервере он вычисляется оставшимся временем существующего фиксированного окна БД, а не предложенным в демонстрации постоянным числом 30. Ответ HTTP также содержит `Retry-After`; повтор не переносит начало окна. Клиент не отправляет запросы в ожидании и разрешает ручной повтор после срока. Таймер не создаёт сетевых запросов и уничтожается при уходе со страницы. Сервер остаётся окончательной проверкой ограничения.

В визуальном тесте S02.error используется явно изолированный 429 с оставшимися 30 секундами. Прежний 401 без ограничения больше не подменяет это состояние макета.

## Повтор команды после 429

В Dart-клиенте и административном `staffApi` исправлена потеря idempotency key при промежуточном 429. До исправления оба регрессионных сценария воспроизводили второй ключ и вторую запись: команда выполнена, ответ потерян → повтор ограничен → следующий повтор. После исправления повтор использует исходный ключ и получает исходный результат. Это не заменяет отдельную проверку повторов после перезапуска процесса/на устройствах.

## Приёмка

Наличие новых снимков не закрывает визуальную приёмку всех экранов. S02/S02.error остаются pending визуально; оставшиеся различия растеризации/интервалов, увеличенный текст, нативные клавиатуры и реальные системы автозаполнения требуют отдельной сверки. Регистрация получила совместимые поля/защиту, но все её состояния не объявлены принятыми.

Основные проверки: `apps/mobile/test/login_screen_test.dart`, `registration_screen_test.dart`, `rate_limit_retry_test.dart`; реальный HTTP — `services/api/test/auth-rate-limit.test.cjs`; административный транспорт — `admin-rate-retry.test.cjs`. Рабочие клиенты используют обычный API. MockClient и ответы с пометкой isolated существуют только в тестах.

Проверки итерации: сборки всех npm-workspace прошли; полный Flutter-набор — 102 passed, 2 skipped (опциональные проверки); полный API-набор — 134 passed, 0 failed/skipped, дополнительно прошёл новый тест административного транспорта. Реальный HTTP-прогон Flutter-клиента прошёл. Полный браузерный сценарий админки/публичного сайта прошёл и снял 72 исходных кадра. После уточнения палитры и проверки просмотра пароля во время ограничения прошли 7 целевых/визуальных тестов и отрисованы 115/115 мобильных состояний без ошибок.
