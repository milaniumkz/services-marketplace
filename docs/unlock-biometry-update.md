# S36 и S15.biometric: разблокировка и биометрия

Дата: 2026-10-19. Проверка поведения и гонок, без визуальной приёмки.

Воспроизведены два отказа до исправления: при ожидающем PIN кнопка биометрии оставалась активной, а после logout завершение старого локального вызова пыталось обновить уже закрытую сессию. Обе проверки падали до изменения.

PIN и биометрия теперь используют один unlockSession с общей блокировкой. Пока выполняется локальная проверка/refresh/загрузка профиля, отключены повторное подтверждение, альтернативные кнопки и обычная навигация. После каждого асинхронного шага проверяются клиент, поколение сессии, пользователь и экземпляр LocalLock. Завершение старого вызова после logout не делает refresh и не меняет новый экран. Профиль записывается в состояние только после проверки его ID против владельца сохранённой сессии.

Отмена биометрии не вызывает API и оставляет блокировку. Неверный PIN и ошибка сети не открывают home. PIN_EXHAUSTED очищает локальную сессию и показывает pin-limit без дополнительного диалога поверх него. Обработчик никогда не объявляет сессию отозванной на сервере только из-за локального forget.

Форма PIN проверяет 6–8 цифр до расходования попытки LocalLock, поддерживая ранее допустимые PIN; новая настройка создаёт 6 цифр. Done отправляет только последнее поле с явно указанным TextInputAction.done либо последнее поле существующей auth-формы. Другие формы по умолчанию не меняют обработку клавиатуры.

Для отдельной настройки биометрии проверены три реальных маршрута приложения: успешный локальный обработчик ведёт к документам, отказ предлагает «Ввести PIN» и открывает pin-setup, завершение сессии не продолжает старую настройку. Back при незавершённом включении остаётся заблокированным общей защитой из предыдущей итерации.

Новый unlock_flow_test использует явно изолированные LocalLock и override refresh для управления задержкой, отменой, ошибкой сети и ошибочным ID профиля. Настоящий KDF/формат хранения отдельно остаётся в local_lock_test с тестовым платформенным каналом. Это не проверка реального сервера, Face ID/Touch ID, аппаратного хранилища или фонового жизненного цикла устройства.

Обновлена старая фикстура widget_test для принятия/отзыва документов: теперь она содержит соглашение и политику, принятие соглашения задано отдельно. Проверка по-прежнему требует блокировку до принятия политики, разрешение после и блокировку после отзыва. После появления второй карточки тест прокручивает список к нужному элементу, а не предполагает, что всё построено в видимой области.

S15.biometric:2 получил ограниченное свидетельство перехода к PIN; Back остаётся pending. Элементы S36 и S36.limit не отмечены визуально или полностью принятыми: текущий экран разблокировки ещё использует форму ввода, а исходный макет требует собственной цифровой клавиатуры с отдельными клавишами. Её геометрия, удаление цифр, биометрическая иконка и все состояния требуют следующей отдельной реализации/сверки. Новые снимки в этой итерации не создавались.

API и нативные каналы этой итерацией не менялись.
