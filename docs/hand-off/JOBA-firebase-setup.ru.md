# Firebase: подключение push JOBA

Проект по скриншоту: **joba-832c7**. Сайт: **https://joba.com.kz/**.
Открыть проект: https://console.firebase.google.com/project/joba-832c7/settings/general

ID проекта не является ключом доступа. В исходниках реализован адаптер FCM, но до регистрации приложений, установки конфигурации и серверных полномочий доставка выключена. Не публикуйте приватный ключ в чате, Git или на сайте.

## 1. Добавить веб-приложение

1. Открыть ссылку выше, войти Google-аккаунтом владельца проекта.
2. В разделе «Ваши приложения» нажать **</>** (Web).
3. Название: **JOBA Web**. Firebase Hosting подключать не нужно: сайт уже работает на своём сервере.
4. Зарегистрировать приложение. Скопировать объект `firebaseConfig` из показанного примера: `apiKey`, `appId`, `messagingSenderId`, `projectId`, `authDomain`, `storageBucket`. Это публичная конфигурация приложения; это **не** серверный приватный ключ.
5. Открыть «Настройки проекта → Cloud Messaging → Веб-конфигурация → Сертификаты Web Push» и создать пару ключей, если её ещё нет. Скопировать публичный ключ **VAPID**.
6. На странице Cloud Messaging проверить, что **Firebase Cloud Messaging API (V1)** включён. Старый server key и Legacy API не используются.

## 2. Добавить Android-приложение

1. «Настройки проекта → Ваши приложения → Android».
2. Имя пакета строго: **kz.joba.services_marketplace**.
3. Название: **JOBA Android**. SHA для самой доставки FCM не требуется.
4. Скачать **google-services.json**. Передать файл разработчику; он используется при будущей сборке и не помещается в публичный Git.
5. Из него нужны публичные настройки Android: `project_info.project_id`, `project_info.project_number` (messagingSenderId), `client[].client_info.mobilesdk_app_id` (appId), соответствующий `api_key[].current_key` (apiKey). Выбирается клиент именно нашего пакета.

Исходники Android подготовлены, но существующий установленный APK сам не получит новый Firebase SDK. Для push в Android впоследствии нужна новая сборка и установка. **По текущему указанию APK не собирается.** Веб обновляется независимо.

## 3. Серверная отправка

Нужны полномочия именно этого проекта, одного ID недостаточно.

1. «Настройки проекта → Сервисные аккаунты → Firebase Admin SDK».
2. Для сервера создать сервисный аккаунт с ролью **Firebase Cloud Messaging API Admin** (`roles/firebasecloudmessaging.admin`) в проекте `joba-832c7`. Не выдавать роль владельца проекта ради push.
3. Если используется JSON-ключ, скачать его и передать администратору по защищённому каналу либо сохранить как GitHub Actions secret для защищённого шага установки на сервер. **Не отправлять содержимое ключа в чат и не коммитить файл.** Текущий workflow не устанавливает такой секрет автоматически.
4. На сервере файл должен находиться по пути `/etc/joba/firebase/service-account.json`, быть доступным на чтение UID 1000 контейнера API и недоступным пользователям сайта. В контейнере используется `GOOGLE_APPLICATION_CREDENTIALS=/run/joba-firebase/service-account.json`; каталог монтируется только для чтения.
5. В серверном `.env` Compose указать публичные конфигурации одной строкой JSON. Не подставлять сюда JSON сервисного аккаунта:

```dotenv
JOBA_FIREBASE_ENABLED=1
JOBA_FIREBASE_WEB_CONFIG='{"apiKey":"ИЗ_WEB","appId":"ИЗ_WEB","messagingSenderId":"НОМЕР_ПРОЕКТА","projectId":"joba-832c7","authDomain":"ИЗ_WEB","storageBucket":"ИЗ_WEB"}'
JOBA_FIREBASE_ANDROID_CONFIG='{"apiKey":"ИЗ_ANDROID","appId":"ИЗ_ANDROID","messagingSenderId":"НОМЕР_ПРОЕКТА","projectId":"joba-832c7"}'
JOBA_FIREBASE_VAPID_KEY=ПУБЛИЧНЫЙ_VAPID
```

6. Пересоздать API через production Compose после установки конфигурации. При штатном обновлении GitHub приватный файл остаётся на сервере, в образ не включается.
7. Проверить `/api/v1/public/push-config`: `enabled=true`, правильный проект и необходимые `platforms`. Этот адрес отдаёт только разрешённые публичные поля, никогда приватный ключ.

При отсутствии настроек оставить `JOBA_FIREBASE_ENABLED=0`: приложение и внутренние уведомления продолжают работать, ложные успешные push не создаются.

## 4. Если потребуется приложение iPhone

1. Зарегистрировать Apple-приложение: bundle ID **kz.joba.servicesMarketplace**.
2. Скачать **GoogleService-Info.plist**, подключить его к Runner в Xcode и добавить соответствующую публичную конфигурацию как `JOBA_FIREBASE_IOS_CONFIG` (включая `iosBundleId`).
3. В Apple Developer включить Push Notifications для этого App ID. В Xcode включить Push Notifications и Background Modes → Remote notifications; provisioning profile должен содержать право APNs. В исходниках добавлены entitlement и background mode; это не заменяет настройки Apple-аккаунта и подпись.
4. В Firebase → Cloud Messaging → Apple загрузить APNs authentication key `.p8`, Key ID и Team ID из Apple Developer. Сам ключ в чат не отправлять.
5. Нужен физический iPhone и подписанная сборка. Минимальная версия iOS для Firebase SDK — 15.

Для Safari на iPhone веб-push доступен начиная с iOS 16.4 для веб-приложения, добавленного на домашний экран; обычная вкладка не заменяет установленное веб-приложение. Разрешение пользователь даёт самостоятельно.

## 5. Проверка реальной доставки

1. Открыть JOBA по HTTPS, войти и пройти обязательные этапы аккаунта.
2. Профиль → настройки уведомлений → **«Включить push на этом устройстве»**, разрешить запрос браузера/Android/iOS.
3. Создать реальное событие со второго тестового аккаунта: новое сообщение, отклик, результат проверки. На первом проверить внутреннее уведомление и счётчики, затем системный push.
4. Повторить при открытом приложении (счётчики обновляются), в фоне и после закрытия окна/приложения. Принудительная остановка Android в системных настройках блокирует доставку до следующего запуска; запрет уведомлений и режимы энергосбережения тоже влияют.
5. Нажать push: открывается раздел событий после авторизации/разблокировки. Защищённые данные загружаются API с проверкой прав, в тексте push нет документов или переписки.
6. Проверить выход из аккаунта и вход другим пользователем: старый аккаунт не должен получать события через это устройство. Токены связаны с действующей серверной сессией; новый вход перепривязывает токен.
7. Проверить запрет уведомлений, смену токена, несколько устройств, настройки категорий и часы тишины. Просроченные FCM-токены исключаются из отправки; временные ошибки повторяются существующей очередью.

Статус «полностью работает» можно подтвердить только после этих проверок с настоящей конфигурацией Firebase и устройством. Скорость доставки зависит также от Firebase, ОС и сети.
