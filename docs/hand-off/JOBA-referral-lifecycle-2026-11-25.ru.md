# Исправление управления реферальной кампанией

Причина обращения подтверждена чтением рабочей конфигурации: в KZ были два собственных черновика владельца, без effective-кампании. Условия совпадали: пять регистраций с кодом, 30 дней текущей подписки, 700 наград, окно ввода кода 30 суток. Старое требование второго сотрудника не позволяло владельцу запустить свой черновик.

## Изменения

- Активный владелец платформы может запускать собственную реферальную кампанию. Для обычных сотрудников независимое подтверждение остаётся обязательным. Другие настройки монетизации и платежей не затронуты.
- Явная кнопка «Запустить кампанию» и сообщение о состоянии: черновик ещё не принимает коды, опубликованная версия принимает их при наличии бюджета.
- Неиспользуемые группы полей награды отключаются, поэтому ошибки скрытой скидки не блокируют выбор бонусных дней.
- «Остановить кампанию» блокирует новые приглашения и сохраняет ранее принятые обещания.
- «Удалить черновик» / «Убрать в архив» скрывает запись из основного списка. Архив доступен отдельно. Физического удаления приглашений, резервов и бонусов нет.
- Действующую кампанию необходимо сначала остановить. Из архива можно создать новую версию, проверить и запустить её.
- Остановка и архив доступны даже при несохранённых правках формы: действие относится к сохранённой версии.
- Причины действий записываются в аудит автоматически, дополнительный комментарий необязателен.
- Запуск, остановка, архив и принятие кодов синхронизированы блокировкой страны; проверяются версии. В стране остаётся одна действующая кампания.

## Проверки

Автоматические API-проверки: запуск собственником; запрет самопубликации обычному сотруднику; фактическое применение кода до/после запуска; однократная награда; замена активной версии; остановка; архив; восстановление новым черновиком; сохранение старых обещаний; неверные версии; лимит бюджета и окно атрибуции.

Реальный Chrome с изолированным memory API: создание, переключение с неверных скрытых полей скидки на подписку, запуск владельцем без второго сотрудника, применение кода и выдача одного тестового бонуса, остановка при несохранённых правках, архив, создание новой версии, повторная публикация и удаление ненужного черновика. Рабочие аккаунты и банковские операции в тестах не используются.

Команды:

```sh
npm run verify
node scripts/verify-referrals-browser.cjs
node scripts/verify-admin-browser.cjs
```

После обновления рабочей версии запускается последний из двух совпадающих черновиков с сохранёнными владельцем условиями. Ранее отклонённые коды пользователям нужно применить повторно. Уже закреплённый пригласивший не меняется.
