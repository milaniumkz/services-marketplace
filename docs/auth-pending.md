# Авторизация — pending implementation

Регистрация и вход: номер телефона + пароль, без SMS вообще. SMS endpoints, SDK и production OTP не создаются. Номер без подтверждения имеет статус unverified login identifier: он не доказывает владение номером, личность и не является фактором сброса пароля. Google/Apple login не обязательны; OAuth не реализован.

Сессию сохраняем; при открытии приложения используем локальный PIN либо поддерживаемую биометрию FaceID/TouchID/Android biometric. PIN и биометрия разблокируют локальный доступ, не заменяют серверную сессию, не восстанавливают истёкшую или отозванную сессию/entitlement. Backend независимо проверяет текущие права. Секреты сессии требуют защищённого OS storage; PIN/биометрические данные не отправляются на сервер. Это требования будущей реализации, не уже готовый механизм.

Recovery ожидает решения пользователя. Подтверждённая почта предлагалась как вариант, но не согласована и не обязательна. Телефон без подтверждения нельзя использовать для восстановления. До утверждения recovery и полного ТЗ не реализуем production регистрацию.

Контракты `packages/contracts/src/auth.ts` содержат только предложенную политику, состояния и demo display guard. Нет credential DTO, паролей, токенов, registration/login/recovery endpoints, SMS-провайдера, проверки личности или настоящего secure storage. Проверка личности остаётся отдельным процессом. Формат/нормализация номера, парольная политика, хеширование, session lifecycle и защита от перебора уточняются в полном ТЗ.
