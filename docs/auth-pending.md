# Авторизация — pending implementation

Источник: [ТЗ JOBA v1.1](spec/services-marketplace-spec-v1.ru.md), разделы 06–08, 24, 28, FR-006–009, T01/T15 и D17.

Целевой вход — телефон + пароль без SMS/телефонных OTP вообще, включая восстановление. Phone status unverified; формат E.164 не доказывает владение. До отправки credentials выбирается регион, автоматический поиск номера по всем базам запрещён. Google/Apple OAuth не обязательны для P1. Пароли — Argon2id, session refresh rotation/revoke и защита от перебора определены в ТЗ; предложенные параметры требуют утверждения.

Сохранённая сессия требует локального PIN или поддерживаемой FaceID/TouchID/Android biometric. Если безопасный механизм недоступен или настройка отклонена, нужен полный вход. PIN/биометрия не выдаёт серверную сессию, не обходит её expiry/revoke или отказ в доступе. Токены требуют OS secure storage; PIN/биометрические шаблоны не отправляются серверу. Проверка личности отдельна. FR-009 делает удостоверение/паспорт по стране и ручную/провайдерскую проверку обязательными для допуска исполнителя; одна загрузка файла не даёт identity_verified.

ТЗ v1.1 исключает почту из пользовательских данных, поддержки и восстановления: email recovery больше не вариант. D17 recovery остаётся открытым без SMS/email; требуется согласовать резервное или ручное доказательство, устойчивое к захвату аккаунта. Непроверенный номер не доказательство владения, reset по нему запрещён. Это release gate; резервный механизм пока не реализован.

Реализованы только demo policy/state contracts и display guard в `packages/contracts/src/auth.ts`. Они не заменяют серверную авторизацию и не реализуют учетные записи, credentials, region-first, secure storage или PIN/биометрию. Register/login/recovery endpoints отсутствуют. [Поддержка и апелляции](moderation-pending.md) при санкции должны оставаться доступны — этот механизм также not_started.

[Требования admin/support/ID](admin-trust-pending.md) синхронизированы с полученным ТЗ v1.1. D17 остаётся открытым release gate; pre-login support capability не даёт доступ к прежним аккаунтным объектам, номер/PIN/IP/новая загрузка документа не дают reset.
