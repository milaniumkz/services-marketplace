# Показатели сервера для владельца

Откройте https://joba.com.kz/admin/ → главная «Обзор платформы» → «Сервер — ресурсы и нагрузка».

Блок доступен только владельцу. Обычные сотрудники, включая администраторов, не получают доступ к API этих показателей.

Показываются реальные показатели всей виртуальной машины:

- число логических ядер, загрузка CPU за интервал и средняя очередь задач за 1/5/15 минут;
- общий, занятый и доступный объём RAM; занято = total − MemAvailable (файловый кэш, доступный приложениям, не считается безусловно занятым);
- объём и использование swap;
- общий и занятый объём корневого диска, место, доступное для записи;
- приём и передача через сетевой интерфейс с маршрутом по умолчанию;
- время работы после запуска сервера и история CPU/RAM/диска за последний час.

Сборщик обновляет снимок каждые 20 секунд. CPU и скорость сети появляются после двух замеров. Замеры старше двух минут скрываются как устаревшие. После перезагрузки счётчики CPU/сети набираются заново; история ограничена последним часом. График — короткая оперативная история, не месячная аналитика.

При устойчивой загрузке CPU выше 85% оценивайте увеличение числа ядер. При постоянно занятой RAM выше 85% вместе с использованием swap проверьте процессы и объём памяти. При заполнении диска выше 85% планируйте расширение или контролируемую очистку. Сам тариф меняется в панели хостинга.

## Установка и проверка

GitHub deployment устанавливает `joba-metrics.service` и `joba-metrics.timer`. Сборщик работает отдельным непривилегированным пользователем `joba-metrics` и пишет только `/var/lib/joba-metrics/metrics.json`. API читает эту директорию через Docker mount `:ro`. Доступ к Docker socket, SSH и произвольным серверным командам из админки не предоставляется.

Проверка на сервере: `systemctl status joba-metrics.timer`, `systemctl status joba-metrics.service`, `journalctl -u joba-metrics.service`. Успешный oneshot-сервис между замерами имеет состояние inactive; это нормально. API: `GET /api/v1/admin/server-metrics`, только после служебного входа владельца.

Проверки исходников: `python3 scripts/test-server-metrics.py`, `node --test services/api/test/server-metrics.test.cjs services/api/test/admin-account-management.test.cjs` после сборки API. Мобильная браузерная проверка админки читает реальные показатели из изолированного локального сборщика и проверяет ширины 320–768 px.
