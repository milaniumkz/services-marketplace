# S36: собственная клавиатура PIN по исходному экрану

Дата: 2026-10-19. Реализована отдельная клавиатура вместо общей формы ввода. Визуальная приёмка остаётся pending.

Экран включает JOBA, инициалы и приветствие сохранённого пользователя, точки, круглые клавиши 0–9 с буквами, биометрическую иконку, удаление цифры и переход к входу с номером/паролем. Геометрия взята из оригинального S36 PNG и HTML: 82px аватар с белой рамкой, заголовок 25px, точки 12px, клавиши 64×60px и интервалы. Позиции уточнены по экспортированному PNG. Системные часы, индикаторы сети и home indicator приложение не подделывает; нативные отступы учитываются отдельно.

Имя и инициалы берутся из сохранённой сессии; если имени нет, показывается общее приветствие и J. Приложение не подставляет Марину из макета и не загружает приватный аватар/профиль до локальной проверки. Марина и две введённые цифры используются только в явно изолированной визуальной фикстуре. В рабочем экране введено 0 цифр при открытии.

Все десять клавиш добавляют цифры, удаление убирает последнюю, шестая цифра нового шестизначного PIN запускает существующую защищённую unlockSession. Ожидание отключает повторный ввод и альтернативные действия. После ответа введённые цифры очищаются; ошибка располагается рядом с точками. PIN не отправляется в API и не выводится в логи. Проверки сессии/refresh/ID профиля из предыдущей итерации сохранены.

LocalLock хранит только несекретную метаинформацию pin_length рядом с существующими salt/hash/failures. Новые PIN имеют известную длину; известные 7–8-значные записи также поддерживаются. В старых записях без длины нельзя безопасно определить её из хеша: допускается ввод 6–8 цифр и появляется явная кнопка подтверждения. Поддержка старого 7-значного PIN проверена настоящим KDF, включая запись без pin_length.

Биометрическая клавиша использует реальную платформенную проверку через существующий LocalLock; отмена не открывает приложение. Ссылка на вход очищает локальную сохранённую сессию и открывает login. Это локальный отказ от сохранённого входа, а не обещание серверного отзыва всех сессий.

Есть ввод физической клавиатурой, Backspace и Enter. Tab/Enter активируют сфокусированную кнопку; экранный диктор получает подписи и действие нажатия, вместо открытого значения PIN озвучивается только число введённых цифр. При увеличении текста высота клавиш растёт, экран прокручивается. Проверены масштаб 1.6 и достижимость ссылки входа. Добавлены kk/sr/be переводы новых подписей.

Проверки: 35 целевых тестов до финального уточнения доступности; полный Flutter-прогон — 140 passed, 1 skipped (реальный HTTP без JOBA_TEST_API_URL), отдельно первоначально упала визуальная съёмка из-за отсутствующих подготовленных иллюстраций. После штатного prepare-visual-assets.py этот визуальный тест прошёл: 115/115 кадров, 0 ошибок. После финального уточнения семантики/Tab повторно прошли 16 целевых тестов клавиатуры и маршрутов. Анализатор — 0 issues. Нативное железо и развёрнутый сервер этой итерацией не проверялись.

На отдельном снимке изолированного состояния с именем/двумя цифрами как в эталоне, 780×1688: по области приложения между системными полосами (y=86…1643) MAE RGB ≈1.6499/255, доля пикселей с яркостным отличием >16 — ≈1.275%. Эти числа описывают конкретную пару снимков; это не универсальный критерий приёмки или доказательство совпадения 1:1. Остаются различия растеризации/позиционирования; реальные системные полосы в widget-снимке не рисуются.
