Срез исходников: `87ec2d8`, 19.10.2026. Это полный перечень проверок, а не список доказанных дефектов. `pending` означает отсутствие индивидуальной приёмки. Существующие действия сначала проверять, исправлять только выявленные расхождения.

[Порядок и критерии работы](../detailed-remaining-plan.md). Идентификаторы контролов сохранены из completion-registry.json. Подписи из макета могут содержать демонстрационные имена и суммы: в приложении они должны заменяться реальными данными, сохраняя компоновку. Изменения владельца имеют приоритет: KG вместо RS, заказчик без подписки.

Всего: **9 кадров, 157 элементов**.

Для КАЖДОГО кадра выполнить четыре небольших этапа:

1. Открыть нужную запись и состояние через приложение; сверить заголовок, поля, порядок блоков, навигацию с эталоном. Служебный выбор ID не заменяет экран.
2. Пройти каждый пункт таблицы ниже: найти обработчик, контракт/API либо локальное действие, проверить результат после перезагрузки и права. Сохранить ссылку на проверку в реестре.
3. Проверить загрузку, пустые данные где применимо, ошибку поля/сервера, повтор, offline/истёкшую сессию, сохранение ввода, клавиатуру и screen reader. Неприменимость обосновать.
4. Исправить найденные отличия и снять кадр в исходном viewport. Приложить эталон, фактический снимок и список разрешённых различий; закрыть функциональную и визуальную приёмку раздельно.
