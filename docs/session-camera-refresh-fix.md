# Сохранение сессии при съёмке и загрузке селфи

Исправлены гонки обновления access/refresh-токенов. Запоздалый 401 от старого access-токена повторяет запрос с уже полученным актуальным токеном. JSON, бинарная загрузка и скачивание используют этот принцип. Обновления сериализуются между экземплярами клиента и вкладками браузера через Web Locks; перед ротацией читается актуальная сохранённая сессия.

До запроса обновления сохраняется UUID операции. Если ответ потерян, повтор с тем же UUID возвращает ту же пару токенов. На сервере хранится только зашифрованный ответ, не более одного на семейство; восстановление возможно лишь пока выданный refresh активен. Другой UUID, отзыв, выход или последующая ротация не позволяют повторно получить действующую сессию. Миграция 0014 создаёт таблицу квитанций; maintenance удаляет истёкшие.

Переподключение событий больше не обновляет токены без причины. Отложенные callbacks старого соединения и соединения при свёрнутом приложении игнорируются. PIN/биометрия и явный отзыв сохраняются. Уже отозванная сессия требует одного обычного входа.

Проверки: параллельные 401, два клиента с общим хранилищем, потерянный ответ и восстановление, загрузка селфи с запоздалым 401, выход во время обновления, изоляция аккаунтов, серверный replay/logout и нативный Web Lock в Chrome. APK не собирается по указанию владельца; изменения нативного клиента войдут в следующую разрешённую сборку.
