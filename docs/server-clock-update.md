# Блок 8: время сервера и истечение доступа

19 октября 2026 введён `ServerClock` для времени отображения. Клиент синхронизируется по UTC `meta.server_time` API и продолжает отсчёт через Stopwatch. Перевод часов телефона после синхронизации не продлевает и не сокращает показанный доступ. Устаревший ответ не переводит время назад; отсутствующая, некорректная или не содержащая часовой пояс метка не уничтожает последнюю корректную синхронизацию. До первого корректного ответа используется время устройства.

Оценка текущего времени отделена от `serverTime`, используемого для отметки уведомлений прочитанными. Более новая метка ответа обновляет этот курсор даже при задержке относительно монотонного отсчёта; старые ответы не уменьшают курсор. Отдельная проверка покрывает этот случай.

По этому времени проверяются активность подписок/грантов, срок подтверждённой рекламной награды, рекламный cooldown, срок доступности реферальной награды и резерв продвижения. «Мой доступ», рекламные состояния и управление подпиской обновляют временные условия без повторных сетевых запросов каждую секунду. При точном равенстве `valid_until` право уже не отображается активным. Сервер остаётся окончательным источником разрешений; UI-таймер не создаёт подписок и наград.

`server_clock_test.dart` проверяет ошибочные часы устройства, их перевод, старые/невалидные метки, удержание времени при отсутствии metadata, границу истечения на двух экранах и окончание cooldown без дополнительного HTTP-запроса. Полный мобильный набор: 175 passed, 2 skipped (HTTP integration без параметра и отдельно включаемая визуальная съёмка). Анализатор: 0 замечаний.

Открыты внешние интеграции, реальные устройства, длительное фоновое выполнение/энергосбережение и полная ручная визуальная приёмка. Это оценка серверного времени для интерфейса, а не проверка точности часов инфраструктуры. Общий пункт плана о времени и доступе не закрывается целиком по этим проверкам.

Отдельно выполнены: `node scripts/verify-mobile-api.cjs` — 1 passed, включая проверку получения UTC-метки и синхронизации часов через настоящий локальный HTTP API; визуальный инвентарь — 115/115, 0 ошибок, без изменившихся снимков. Съёмка использует изолированные данные и не является визуальной приёмкой.

Последующее уточнение: [массовое прочтение уведомлений](notification-read-update.md) использует границу первой страницы `data.meta.read_before`, а не глобальный `serverTime` произвольного последующего ответа. Монотонные часы доступа продолжают работать отдельно.
